本書の読み方

木を見るための、三つの約束

本書は、再帰という考え方を、計算の途中に現れる木から理解する小冊子です。迷路、ハノイの塔、フラクタル、麻雀を順に取り上げます。コードの文法を覚えることよりも、「いま何を解こうとしていて、次に何を任せ、どこへ戻るのか」を追うことを大切にします。

第一の約束は、同じ処理と、同じ呼び出しを区別することです。同じ関数を同じ引数で2回呼んでも、それは2回の出来事です。呼び出しの木には別々のノードとして描きます。

第二の約束は、木の全体と、いま実行中の経路を区別することです。木は過去や未来の呼び出しまで含めて描けます。一方、スタックが覚えているのは、まだ終わっていない呼び出しの列です。

第三の約束は、帰り先と停止条件を区別することです。呼び出した相手がいつまでも戻らなければ、帰り先が記録されていても処理は先へ進みません。

本文の角括弧の番号［1］などは末尾の参考文献に対応します。図、牌姿、コード、証明の説明は本書用に制作しました。資料が裏づける標準的な知識と、本書の見方である「木構造生成装置」は区別して扱います。

Pythonコードを飛ばしても本文は読めます。実行したい人向けに、標準ライブラリだけで動く examples.py を付属しました。掲載例は通常の同期的な関数呼び出しを対象とし、並行処理や継続の特殊な制御までは扱いません。

ここに注目

「ノード＝1回の呼び出し」という単位を、最初に決める。

RECURSION / INTRO

はじめに

まったく違う問題から、同じ木が現れた

迷路で右へ進んでみたら行き止まりだった。最後の分岐へ戻り、今度は左を試す。この行動には、前へ進む規則だけでなく、途中の仕事を覚えておく仕組みが要ります。

ハノイの塔では、いちばん大きな円盤を動かす前に、その上の円盤を別の棒へ移さなければなりません。「小さな塔を移す」という仕事の中に、さらに小さな塔を移す仕事が含まれています。

三角形を3個の小さな三角形に置き換え、それぞれに同じ操作を施すと、自己相似な模様が現れます。麻雀の手牌から3枚の組を取り除き、残った牌をまた調べると、分解の候補が枝分かれします。

これらを紙に描くとき、問題全体を上に置き、そこから生まれた部分問題を下へ並べ、線で結んでみましょう。何度も現れるのは木です。ただし、木が表しているものを揃える必要があります。迷路そのものは輪を含みえますが、その探索を行った呼び出しの履歴は木として描けます。

本書でたどるのは、この区別を含めた発見です。再帰は単に「自分自身を呼ぶ」という奇妙な文法ではありません。一つの仕事を、同じ形式の小さな仕事へ展開することで、親子関係を持つ計算の構造が現れます。

まず一本道の再帰から始め、分岐、復帰、図形、探索を少しずつ加えます。最後には、重複する部分問題をまとめて木からグラフへ進みます。木が見えるようになると、木だけでは表せないものも、はっきり区別できるようになるはずです。

第1章　再帰関数とは何か

1.1　「自分を呼ぶ」を、小さな仕事に直す

関数とは、入力を受け取り、決めた手順を実行するまとまりです。数を返すものもあれば、図を描いたり円盤の移動を記録したりするものもあります。関数の実行中に、その関数をもう一度呼び出すことを再帰と呼びます。［1］

例として階乗を考えます。4! は「4の階乗」と読み、4 × 3 × 2 × 1 = 24 を表します。この積の後半は3!ですから、4! = 4 × 3! と書けます。同様に3! = 3 × 2!、2! = 2 × 1!です。

一般に、0以上の整数nについて、0! = 1、n ≥ 1ならn! = n × (n−1)!と定義できます。0! = 1という約束は、1! = 1 × 0!とのつながりを保ち、何も掛けない積を1とする扱いにも一致します。

ここで4!を求める係は、3!の中身をすべて自分で展開しなくても、「3!を求める係」に任せられます。ただし別の人を用意する必要はありません。同じ計算手順を、入力だけ変えてもう一度実行すればよいのです。

基本条件は、他の呼び出しに頼らず答えられる場合です。再帰規則は、それ以外をどの部分問題に結びつけるかを定めます。階乗ではnが1ずつ減るため、0以上の整数から始めれば必ず基本条件へ到達します。

この二つに加え、「本当に小さくなるのか」を確かめましょう。nを増やし続ける手順にも自分自身の呼び出しはありますが、それだけでは計算を終えられません。

ここに注目

基本条件：0! = 1　／　再帰規則：n! = n × (n−1)!

1.2　下へ呼び、上へ答えを返す

4!の処理は、3!を呼んだ瞬間に消えるわけではありません。「3!が分かったら4を掛ける」という続きが保留されます。3!も同様に、2!を待ちます。いちばん奥の0!だけは、その場で1を返せます。

図1.1の左側は呼び出す順序、右側は値が確定する順序です。下向きに問題を小さくし、上向きに答えを組み立てます。呼び出しの向きと、結果を返す向きが逆になることに注目してください。

Pythonコードを読む
def factorial(n):
    if n < 0:
        raise ValueError("n must be nonnegative")
    if n == 0:
        return 1
    return n * factorial(n - 1)

1.3　スタックは「まだ終わっていない仕事」

関数を呼ぶと、通常は引数や局所変数、呼び出し後に再開する位置などを保持する実行の記録が作られます。これをフレームと呼びます。後から呼ばれた仕事を先に終えるよう重ねたものが、コールスタックです。［2］

図1.2では、下にある仕事ほど先に始まりました。0!が返るとそのフレームが外れ、すぐ下にある1!の続きが再開されます。4!へ一足飛びに戻るのではありません。

同じnという名前でも、各フレームは別の値を持ちます。3!の途中で2!を呼んでも、親のn = 3が2へ書き換わるわけではありません。この独立した実行の記録が、入れ子の処理を支えます。

ここに注目

木の全体は履歴の図。スタックは、その時点で生きている根から現在までの経路。

1.4　一本道も、木の一種である

階乗の呼び出しでは、一つのノードから子が一つだけ生まれます。枝分かれがなくても、これは根付き木の特別な形です。根とは最初の呼び出し、辺とは「この呼び出しが、その呼び出しを始めた」という関係を表します。

根以外のノードには親が一つあります。自分を呼んだ実行が一つだからです。同じ関数名が並んでも、n = 4の実行とn = 3の実行は同一ではありません。さらに、同じnで2回呼べば、その2回も別ノードです。

階乗は繰り返しでも計算できます。resultを1から始め、1、2、3、4を順に掛ければ24になります。再帰は仕事を入れ子の呼び出しで表し、反復はループの中で状態を更新します。答えが同じでも、途中の情報の持ち方は違います。

再帰を書けば、必ず大きな木をメモリ上に保存するわけではありません。通常、計算に必要なのは現在のスタックだけです。完了した枝は忘れられますし、後で見る呼び出しの木は、実行記録から描いてもかまいません。

また、通常の関数呼び出しの入れ子は、再帰を使わない場合にも木として描けます。再帰の特徴は、同じ規則を繰り返し適用して、入力に応じた深さや分岐を生める点にあります。木という形だけで再帰を定義しているわけではありません。

この章のまとめ

再帰では、部分問題を呼び出し、結果が返るまで続きを保留します。呼び出しを出来事として描くと木が現れ、スタックはその木の一つの経路を保持します。［1, 2］

第2章　迷路探索

2.1　地図には輪があり、履歴には親がある

図2.1の左は、小さな迷路を通路と分岐点だけに簡略化した地図です。Sを入口、Gを出口とします。S、A、C、DをたどるとSへ戻れるため、この地図には輪があります。点を頂点、点の間の通路を辺と呼ぶと、迷路はグラフです。

右は、SからAへ進み、まずBを調べる探索の履歴です。Bから戻った後、AからCへ、さらにD、E、Gへ進みます。DにはSから直接行く通路もありますが、今回はCから初めて発見しました。したがってDの親はCです。

ここに注目

「場所の親」と「今回その場所を探索した呼び出しの親」は別の話。

2.2　行き止まりは、全体の失敗ではない

深さ優先探索、略してDFSは、選んだ枝をできるだけ奥まで調べてから、別の枝へ移る探索法です。Bでは未訪問の隣接点がなくなります。それでもAにはCという候補が残っています。

そこでBの探索を終えて、Bを呼んだAへ戻ります。Aの処理は、「Bの探索の結果を確認した次」から再開します。Aを入口として一から探索し直すわけではありません。このように選択を取り消し、前の分岐から別の可能性を調べる操作をバックトラックと呼びます。［2, 3］

ここに注目

失敗という結果も、親に返せる有用な情報。「この枝には出口がなかった」と分かる。

2.3　訪問済みの印は、何を防ぐのか

SからA、C、Dへ進んだ後、DからSへまた進めば、同じ輪を何度でも回れてしまいます。呼び出しの木では、Sというラベルの別ノードが、そのたびに追加されます。木に循環がなくても、同じ場所の探索は繰り返せるのです。

出口への到達可能性を調べる今回の問題では、訪問済み集合を共有し、初めて入った頂点をすぐ登録します。既に登録された頂点へは再帰しません。有限の迷路なら、初訪問を生む呼び出しは頂点数を超えません。［2］

一方、いまの経路を保存するpathは別です。行き止まりから戻るときには末尾を消しますが、訪問済みの印は残します。pathは「いまどこを通っているか」、visitedは「これまでどこを調べたか」を表しているからです。

この区別は、目的が変わると見直しが必要です。すべての単純経路を列挙したい場合には、一度訪れた場所を全体で禁止すると別経路を捨ててしまいます。また、鍵を拾うと通れる扉が増える迷路では、場所だけが同じでも状態は同じではありません。位置と鍵の有無を合わせて管理します。

図2.1で得られるS-A-C-D-E-Gは5本の辺を通ります。しかしS-D-E-Gなら3本です。DFSは一つの道を見つけても、それが最短であるとは限りません。最短の辺数を求める幅優先探索は、第7章で比較します。

ここに注目

訪問済み管理の単位は、問題の「状態」。いつでも位置だけで十分とは限らない。

2.4　選択と復帰をコードにする

次の関数は、隣接点を列挙する辞書graphを受け取り、入口から出口への経路を一つ返します。見つからなければNoneです。内側のvisitが、頂点一つ分の探索を担当します。図2.1では、付属コードに記した隣接順で実行します。

Pythonコードを読む
def dfs_path(graph, start, goal):
    visited = set()
    path = []
    def visit(v):
        visited.add(v)
        path.append(v)
        if v == goal:
            return True
        for w in graph[v]:
            if w not in visited and visit(w):
                return True
        path.pop()
        return False
    return path if visit(start) else None
この章のまとめ

迷路はグラフ、初訪問の履歴は木。DFSは深く進み、失敗したら親の続きへ戻る。有限グラフでの停止には訪問済み管理が効く。

第3章　ハノイの塔

3.1　大きな円盤を動かす前に

3本の棒A、B、Cと、大小の円盤を用意します。最初はAに、大きい順に下から積んであります。目的は全部をCへ移すこと。1回に動かせるのは一番上の円盤1枚だけで、大きな円盤を小さな円盤の上に置いてはいけません。［1］

円盤が1枚ならAからCへ動かして終わりです。2枚なら、小をAからBへ、大をAからCへ、小をBからCへ移します。3枚ではどうでしょう。大きな円盤を動かすには、その上の2枚をどかす必要があります。

ここで「2枚を移す仕事」を一まとまりとして考えます。まず上の2枚をAからBへ移す。その間はCを補助に使う。次に最大の円盤をAからCへ動かす。最後にBの2枚をCへ移す。その間はAを補助に使います。

上の2枚を移すあいだ、下にもっと大きな円盤があっても邪魔にはなりません。小さな円盤は、その上に合法的に載せられるからです。この性質により、同じ手順を塔の一部分へそのまま適用できます。

n枚を移す課題をH(n, 出発, 到着, 補助)と書きます。最初の仕事はH(3,A,C,B)。そこからH(2,A,B,C)とH(2,B,C,A)という二つの子が生まれ、その間に円盤3の移動が入ります。

注意したいのは、子の引数です。円盤の枚数を一つ減らすだけでなく、棒の役割も入れ替わります。木の形が同じでも、具体的な移動先はラベルによって決まります。

ここに注目

小さい塔を移す → 最大の円盤を1回動かす → 小さい塔を重ねる。

3.2　3枚の移動を、手で確かめる

図3.1を上から行ごとに、左、右の順で読んでください。円盤番号は小さいものから1、2、3です。最初の3手で円盤1と2がBへ移り、4手目で円盤3がCへ進みます。残り3手で小さい塔をCへ重ねます。

ここに注目

移動回数は3 + 1 + 3 = 7。前半と後半は、ともに2枚の塔を移す仕事。

3.3　4枚の塔から15個の呼び出しへ

次は4枚です。根のH(4,A,C,B)は、左のH(3,A,B,C)と、右のH(3,B,C,A)を呼びます。それぞれが2個のH(2,…)を呼び、さらに各H(2,…)が2個のH(1,…)を呼びます。

次の図3.2が、その全体です。各囲みは1回の呼び出しを表し、下段に、その呼び出し自身が担当する1回の円盤移動を記しています。先頭の01～15は移動の順番です。

1枚で止めるので、葉はすべてH(1,…)です。葉以外は必ず子を二つ持ち、葉はすべて同じ深さにあります。この意味で「完全二分木」、英語ではより明確にperfect binary treeと呼ぶ形になります。complete、full、perfectの訳語は教材によって揺れるため、本書ではこの形の定義を優先します。

呼び出しの開始順と、円盤の移動順は違います。H(4,…)は最初に始まりますが、円盤4を動かすのは左の7個が終わった後の8手目です。根は、開始時刻も実際の作業時刻も最初、というわけではありません。

根の二つの枝が、左部分木と右部分木につながっています。まず左側の01～07をたどり、根の08を実行し、右側の09～15へ進んでみてください。左右の木は形が同じで、棒の名前だけが異なります。

ここに注目

数える対象を固定する：基本条件をn = 1とした、再帰関数Hの呼び出しだけを描く。

3.4　4枚の完全二分木

左部分木は「上の3枚をAからBへ移す」という仕事です。右部分木は「Bに待機した3枚をCへ重ねる」という仕事です。囲み上段が呼び出し、下段がその呼び出しの担当する移動です。

左側の01～07、根の08、右側の09～15の順にたどります。画面が狭い場合は図を横にスクロールするか、「図を拡大」で全体を開いてください。

ここに注目

01～07：A上の3枚をBへ。08：円盤4をAからCへ。09～15：B上の3枚をCへ。右部分木が終わると、根の呼び出しも終了する。

3.5　左、根、右という読み方

二分木を「左部分木、自分自身、右部分木」の順に処理することを中順走査と呼びます。ハノイの手順は、まさにこの位置に円盤移動を置いています。次のコードではmovesへ追加する行が、自分自身の仕事です。

Pythonコードを読む
def hanoi(n, src, dst, aux, moves):
    if n < 1:
        raise ValueError("n must be positive")
    if n == 1:
        moves.append((1, src, dst))
        return
    hanoi(n - 1, src, aux, dst, moves)
    moves.append((n, src, dst))
    hanoi(n - 1, aux, dst, src, moves)

付属コードでは、moves = []を作り、hanoi(4, "A", "C", "B", moves)と実行します。要素は円盤番号、移動元、移動先の組です。木を先順、つまり根から処理すると、まだ上に小さな円盤があるのに円盤4を動かそうとしてしまいます。木の形だけでなく、作業を実行する位置が重要です。

ここに注目

n = 0なら何もしない版では、4枚の呼び出しは31回。そのうち16回は0枚の葉で、移動は行わない。移動回数はどちらも15回。

3.6　15という数を、二通りで数える

深さ0に根が1個、深さ1に2個、深さ2に4個、深さ3に8個。4枚の木は、その合計15個です。n枚では深さn−1まであり、1 + 2 + … + 2ⁿ⁻¹ = 2ⁿ − 1となります。

別の数え方は、塔を一段小さくする漸化式です。左にT(n−1)回、中央に1回、右にT(n−1)回。したがってT(n)+1 = 2{T(n−1)+1}です。T(1)+1 = 2から、T(n)+1 = 2ⁿ、すなわちT(n) = 2ⁿ−1が得られます。［4］

木の段を足しても、根で左右へ分けても、同じ数になります。数式の2は子の数、最後の+1は自分自身の作業に対応しています。

ここに注目

移動回数の漸化式：T(1) = 1、T(n) = 2T(n−1) + 1。

3.7　なぜ、これが最小なのか

漸化式は、この手順が何回動かすかを教えてくれます。しかし、それだけではもっと短い別の手順がないとは言えません。最小性には下限の議論が必要です。

最小移動回数をM(n)とします。最大の円盤を最初に動かす直前、小さいn−1枚は残りの1本へすべて積まれていなければなりません。その準備には少なくともM(n−1)回かかります。

また、最大の円盤が目的地Cへ最後に入る直後、小さいn−1枚は別の1本に積まれています。それらをCへ重ねるには、少なくともM(n−1)回必要です。最初の最大円盤の移動以前と、最後の移動以後の区間は重なりません。途中に最大円盤の移動が少なくとも1回あるので、M(n) ≥ 2M(n−1) + 1です。

再帰手順は、ちょうどその回数で実現します。M(1) = 1から帰納的にM(n) = 2ⁿ − 1。これで、実現可能な手順と、それより減らせない理由が揃いました。

一方、同時に保留する呼び出しは根から葉までのn個です。全体の仕事量は指数的に増えても、コールスタックの深さはnです。付属コードのように全移動をリストへ保存すれば、その出力の保存には2ⁿ − 1個分の領域が別途必要になります。

この章のまとめ

1枚で止まるハノイの呼び出し木は、各段が満たされた二分木です。中順走査が移動順を与え、木全体のノード数が移動回数に一致します。ただし、最小性はノード数を数えるだけでは証明できません。

第4章　フラクタル

4.1　三角形を、三つの三角形で置き換える

正三角形の各辺の中点を結ぶと、元の半分の辺長を持つ三角形が4個できます。中央の逆三角形の内部を除き、角に残る3個へ同じ操作を繰り返します。これがシェルピンスキーの三角形を作る標準的な方法です。［5］

段階0を元の三角形とすると、段階1では3個、段階2では9個、段階3では27個の小三角形が残ります。「いま扱う三角形」を親、「次に扱う3個」を子とすれば、呼び出しの木は三分木になります。

4.2　木の枝に、図形の住所を付ける

上の子をA、左下をB、右下をCと名付けます。全体のAを選び、その中のBを選べばABです。2段たどる住所は9個あり、図形の9個の小領域と対応します。

木はどの順で部分領域を作ったかを記述し、図形はそれらが平面のどこに置かれたかを示します。幾何学的な位置や縮小率は、木の形だけからは分かりません。枝に対応する変換の規則が必要です。

4.3　1.585次元は、何を数えているのか

線分を半分の長さの部分で覆うには2個、正方形を半分の辺長の正方形で覆うには4個必要です。それぞれ2¹、2²個なので、拡大率2と個数の関係に次元が現れています。

シェルピンスキーの三角形の極限集合は、半分に縮めた自分自身3個で構成されます。この対応から2ᴰ = 3と置けば、D = log(3) / log(2) ≈ 1.585となります。logは対数で、ここではどの底で計算しても比は同じです。

これは相似性から求める相似次元です。一般の自己相似集合では、縮小コピーが大きく重なると、この計算だけで実際の次元は決まりません。今回の三角形は適切な分離条件、いわゆる開集合条件を満たし、ハウスドルフ次元、ボックス次元もこの値に一致します。［6］

面積でも確かめましょう。1回の操作で残る面積は元の3/4。段階kでの面積は元の(3/4)ᵏ倍で、無限に繰り返すと0へ近づきます。面積が0だから、点が一つも残らないということではありません。外周や、細分化の境界などは残ります。

ここで有限と無限を混同しないことが大切です。有限段階の黒い三角形にはまだ内部と正の面積があり、その集合のハウスドルフ次元は2です。1.585は、無限の細分化で得られる極限集合についての値です。印刷された図は、その有限の近似にすぎません。

ここに注目

縮小率1/2のコピーが3個：3 × (1/2)ᴰ = 1。

4.4　IFSは、枝の規則を座標で書く

正三角形の頂点をa、b、cとします。点xを頂点aとの中点へ送る写像をfₐ(x) = (x + a) / 2と定めます。fᵦ、f𝒸も同様です。各写像は距離を1/2に縮め、図形全体を三つの角へ写します。

複数の縮小写像をひと組にしたものを、ここでは反復関数系、IFSと呼びます。図形Sのコピー三つを合わせる操作は、fₐ(S) ∪ fᵦ(S) ∪ f𝒸(S)です。極限の三角形Kでは、K = fₐ(K) ∪ fᵦ(K) ∪ f𝒸(K)という関係が成り立ちます。［6, 7］

図4.2のABは、全体をAへ写し、その領域の中でB側を選ぶという住所です。写像で書けばfₐ(fᵦ(S))。右側の写像から計算する記法と、外側から読む住所の順が異なる点には注意してください。

この図を作るために、関数の自己呼び出しは必須ではありません。現在の三角形の一覧を用意し、ループで次段階の一覧へ置き換えても同じ図ができます。再帰的な構造を持つ対象と、再帰関数で実装することは、区別できます。

ハノイの木も、左右に同じ形の小さな木を含みます。しかし、それだけでフラクタル次元が決まるわけではありません。縮尺、空間への配置、無限の極限をどう定義するかが必要です。「形の繰り返しが見える」と「数学的なフラクタルである」の間には、この追加の条件があります。

ここに注目

再帰木は生成の関係を記述する。IFSは、その枝に幾何学的な変換を与える。

4.5　コラム：ハノイには、もう一つの図がある

ハノイの塔の合法状態を点にし、1回の合法な移動で行き来できる状態を線で結びます。2枚なら、大小それぞれの円盤の所在をA、B、Cから選べるので9状態です。棒ごとに大きい順に積む配置が一意に決まるため、一般には3ⁿ状態あります。

ここに注目

最大円盤の所在で3群に分けると、それぞれが小さいハノイグラフ。群の間を特定の合法移動が結ぶ。

4.6　二分木と三角形を、混ぜない

図4.3の状態グラフでは、最大円盤をAに固定した群、Bに固定した群、Cに固定した群が、それぞれn−1枚の状態グラフになっています。二つの群をつなぐには、小さい円盤全部が第三の棒へ退避していなければなりません。そのため群間には限られた橋だけが架かります。

この「3個の小さなグラフを結ぶ」再帰的構成が、シェルピンスキー型の三角形状の見た目を生みます。学術資料ではHanoi graphとSierpiński gasket graphが別々に定義され、比較されています。形が似ているからといって、両者を同じ有限グラフと断定することはできません。［8］

第3章の二分木は、決められた解法の呼び出し履歴です。頂点は部分課題で、1枚で止めれば2ⁿ − 1個。一方、この状態グラフの頂点は円盤の配置で、3ⁿ個です。前者は計算の手順、後者はゲーム内で可能な移動全体を表しています。

3枚なら、呼び出し木は7ノード、状態グラフは27頂点。最短手順は状態グラフ上の7本の辺を通り、開始を含めて8状態を訪れます。7ノードと8状態を対応させようとして混乱するのは、ノードの意味が違うからです。

この章のまとめ

図形の再帰では、枝に位置と縮小率が加わります。有限の生成段階と無限の極限は別物です。ハノイの呼び出し木、合法状態グラフ、シェルピンスキーの図形は、関連していても同一の対象ではありません。

5.1　14枚を、3・3・3・3・2に分ける

麻雀を知らない人は、決められた模様のカードを組に分けるパズルだと考えてください。数のある牌は、萬子・筒子・索子の3系列に1～9があり、ほかに7種類の字牌があります。合計34種類で、同じ種類の牌は4枚ずつあります。［9］

通常の完成形は、3枚の組を四つと、同じ牌2枚の組を一つ作った形です。3枚の組を面子、2枚の組を雀頭と呼びます。面子には、同種3枚の刻子と、同じ系列で数が連続する順子があります。

5.2　最初の分岐は、雀頭をどれにするか

図5.2は、11122233345677萬という14枚の手牌です。同じ数字を並べて表し、すべて萬子とします。見た目では、111・222・333・456・77と分けられそうです。しかし、計算機にとっては、これは候補の一つです。

たとえば77を雀頭として除くと、残りは111222333456です。次に111を刻子として除けば、222333456が残ります。同じ問いを、9枚の牌に対してもう一度行えばよいわけです。

また、牌を並べた順番は判定に影響しません。本書のコードは、各種類が何枚あるかという34個の整数で状態を表します。同じ牌を個体として区別せず、重複する数は正確に残せます。

ここに注目

雀頭の候補は11、22、33、77。いずれかを2枚除き、残った12枚が面子だけになるかを調べる。

5.3　成功する枝、失敗する枝

図5.3は雀頭を77にした後の探索です。残り333456から、333を除けば456だけになり成功します。ところが345を除くと336が残り、面子を作れず失敗します。

5.4　一番小さい牌から選べば、漏れない

残り牌のうち、番号が最も小さい牌iを一つ選びます。正しい面子分解があるなら、この牌も必ずどこかの面子に入っています。その入り方は、同じ牌3枚の刻子か、iから始まる順子のどちらかです。

なぜ順子の真ん中や最後を考えなくてよいのでしょう。たとえば最小の牌が3なら、123や234へ入るには1または2が要ります。しかし、残りには3より小さい牌がありません。このため、345だけを調べれば十分です。系列の境界と字牌の制約も守ります。

候補の面子を除いて同じ判定を繰り返し、空になれば成功です。候補が一つもなければ失敗。これで、すべての牌を使い切る分解があるかどうかを判定できます。選ぶ順番を揃えることで、同じ面子集合を取り出す順序だけ変えた探索も減ります。

この手順の正確さは、小さい問題から説明できます。空の集合は、追加の面子を必要としません。空でない集合の正しい分解には最小牌を含む面子があり、その候補をすべて試します。候補を外した後の判定が正しければ、元の判定も正しい。この構造は数学的帰納法と対応します。

標準形で雀頭を先に除くと、残りは12枚です。面子を1個除くごとに3枚ずつ減り、12、9、6、3、0枚となります。深さは限られているので、一つの枝で無限に牌を取り除くことはありません。

ここに注目

「全部の並べ方を試す」必要はない。正しい分解が必ず含む最小牌の行き先を、漏れなく試す。

5.5　残り牌だけを受け取る再帰関数

countsは34種類の枚数を表すタプルです。番号0～8が萬子、9～17が筒子、18～26が索子、27～33が字牌です。先頭の@cacheは、第7章で扱う結果の保存です。外しても判定結果は変わりません。

Pythonコードを読む
from functools import cache

@cache
def meldable(counts):
    if not any(counts):
        return True
    i = next(i for i, x in enumerate(counts) if x)
    c = list(counts)
    if c[i] >= 3:
        c[i] -= 3
        if meldable(tuple(c)):
            return True
        c[i] += 3
    if i < 27 and i % 9 <= 6:
        if c[i + 1] and c[i + 2]:
            for j in (i, i + 1, i + 2):
                c[j] -= 1
            if meldable(tuple(c)):
                return True
    return False
ここに注目

i % 9 ≤ 6は、順子の先頭が1～7である条件。子にはコピーした枚数列を渡すため、子の変更が親の状態を壊さない。

抜き北を採用する場合、既に抜いた北を通常の手牌へ数えない扱いも必要です。副露や槓がある場合は、確定済みの面子を分離し、残りに必要な面子数を調整します。付属の待ち関数は、こうした拡張を入れる前の、閉じた13枚に対象を限定しています。

5.8　同じ残り牌は、同じ問いになる

111222333456という残り牌から、111、222、333を除くと456が残ります。一方、123を3回除いても456です。取り出した面子は違っても、残り牌の分解可能性を問うだけなら、最後に残った問題は同じです。

一度456が分解できると分かれば、別の枝から来たときも同じ答えを使えます。そのために保存するキーは、牌の並び順ではなく、34種類の枚数列です。@cacheがこの引数と返り値を対応づけて記録します。［11］

ただし、この単純な例では、成功が一つ見つかった時点で探索を打ち切るため、両方の枝を実際にたどるとは限りません。図は可能な分岐を示しており、実行された呼び出しの木は、枝の順番や早期終了によってもっと小さくなります。

また、「残り牌だけで答えが決まる」という条件が重要です。得点や役まで調べるなら、それ以前に選んだ面子や和了牌の位置などが関係することがあります。分解の有無を返す関数のキャッシュを、そのまま点数計算に転用することはできません。

第6章　親子関係があるから迷子にならない

6.1　「誰が呼んだか」は、一つに決まる

ここまでの四つの題材には、前へ進む規則の違いがありました。迷路では隣の頂点、ハノイでは小さい塔、三角形では縮小領域、麻雀では面子を除いた残り牌です。それでも、子の処理を終えた後に戻る関係は共通です。

通常の同期的な呼び出しでは、一つの実行を始めた呼び出し元は一つです。したがって、出来事ごとにノードを作れば、根以外のノードに親が一意に定まります。親を繰り返したどると、根への経路も一つに決まります。

同じ関数が何度も現れても問題ありません。父親の名前を関数名だと思うと紛らわしくなりますが、親とは「今回のこの実行を始めた、特定の実行」です。呼び出しごとの番号を振れば、区別は明確になります。

では、木を描くだけで計算機が帰り先を知るのでしょうか。そうではありません。木は関係の表現であり、実際の再開位置を保持するのがフレームやスタックです。数学的に親が一意であることと、機械がその情報を記録していることの両方が必要です。

再帰を木として理解する実用的な価値は、「全部を一度に考えなくてよい」点にあります。子には契約した仕事を任せ、親はその結果を受け取った後の続きを持ちます。どの枝にいるのかを図にすれば、局所的な手順と全体の位置を結びつけられます。

ここに注目

親が一意なのは、状態をまとめる前の「呼び出しの出来事」の木。

6.2　スタックに載っているのは、一つの枝

図6.1の左は履歴全体の模式図です。濃い線だけが、いま保留されている呼び出しをたどる経路です。右のスタックは、その順序を重ねて表しています。［2］

現在の呼び出しが返ると、そのすぐ下のSが再開します。Sが終わればP、その後に根です。右の枝Qがまだ始まっていないなら、その呼び出しのフレームはまだありません。木全体をいつも持っているのではないのです。

ここに注目

呼び出しの総数と、同時に生きている呼び出しの数は違う。木の大きさと深さを別々に見る。

6.3　帰り道があることと、帰れること

「親がいるから迷子にならない」は、戻る相手を特定できるという意味です。いつか必ずそこへ戻るという保証ではありません。子がさらに子を呼び続ければ、親は待ったままです。

たとえばf(n)が無条件にf(n+1)を呼ぶなら、自然数の列はいつまでも先へ進めます。各ノードの親は一意ですが、基本条件には到達しません。実際のPythonでは有限の資源や再帰深度の制約により、正常終了より先に例外が起こりえます。

停止を証明する一つの方法は、呼び出すたびに厳密に減る0以上の整数を見つけることです。階乗ならn、ハノイなら枚数、図形なら残りの段数、麻雀なら残り牌数。有限の分岐と、各呼び出し内の有限の処理も確認すれば、全体が有限で終わることを説明できます。

迷路では、位置に大小を付ける代わりに、未訪問の頂点を一つずつ減らします。有限グラフで再訪問を防ぐから、いつまでも新しい頂点へ進むことはできません。ただし出口が見つかる保証と、探索が終了する保証は別です。出口がなければ、有限の探索を終えて失敗を返します。

もう一つ、復帰してもデータの変更が自動で取り消されるとは限りません。共有の配列から牌を引いたなら、別の枝を試す前に戻すか、コピーで分離する必要があります。スタックは制御の続きを記憶しますが、プログラム中の変更すべてを巻き戻す装置ではありません。

ここに注目

停止の目印を用意するだけでは足りない。その目印へ到達する理由も必要。

6.4　木を描くと、何を点検できるか

再帰を考えるときは、最初に根へ「この呼び出しが完成させる仕事」を書きます。次に、子へ渡す入力と、返ってきた後の処理を書きます。最後に葉が何を意味するかを確かめます。この三段階で、関数名だけでは見えなかった契約が現れます。

ハノイなら「n枚を出発から到着へ合法的に移す」、麻雀なら「この残り牌をすべて面子に分けられるか」です。子が何を保証するのかが曖昧だと、親の続きを正しく書くことも難しくなります。

図の枝が同じ大きさの問題へ戻っていれば、停止条件を疑えます。似たラベルの部分木が大量に現れれば、重複計算に気づけます。深い一本道なら、仕事量が少なくてもスタックの深さが問題になりえます。広い木なら、同時に全ノードを保存する方法の負担を予測できます。

木は、処理の順番までは完全に指定しません。左右どちらから進むか、自分の仕事を子の前・間・後のどこで行うかは、別に決めます。ハノイの中順走査と、階乗の戻りながらの乗算が異なるのは、この位置が違うからです。

この章のまとめ

親子関係は復帰先を一意にします。スタックはその関係に沿って続きを再開します。しかし、停止、入力の正しさ、共有データの復元は別途点検する必要があります。「帰り道が分かる」という直感を、この範囲で使うと強力です。

第7章　木からグラフへ

7.1　同じ問いを、別々の枝で解いている

フィボナッチ数をF(0) = 0、F(1) = 1、F(n) = F(n−1) + F(n−2)で定めます。F(4)を素直に計算すると、左のF(3)の中にも、右にもF(2)が現れます。二つは別の呼び出しですが、求めている値は同じです。［12］

図7.1の右では、同じ引数のノードを一つにまとめました。辺は「計算するために、その値が必要」という依存を表します。F(2)には二つの呼び出し元から辺が入るため、もう木ではありません。

7.2　メモ化と、下から埋める計算

一度求めた答えを引数とともに保存し、同じ引数なら再利用する方法がメモ化です。F(2)を初めて計算したときに1を保存すれば、次はその値を取り出せます。保存できるのは、必要な状態が同じなら答えも同じになる場合です。［11］

呼び出された値だけを必要に応じて計算する方法を、上から解く方法、トップダウンと呼びます。逆に、F(0)、F(1)、F(2)、…と依存先を先に計算して表を埋める方法は、ボトムアップです。重なる部分問題の結果を再利用する動的計画法には、どちらの進め方もあります。［12］

F(n)までの異なる状態はn+1個。メモ化または順序を決めた表の計算なら、足し算の回数はnに比例します。ただし数値自体が大きくなるので、巨大な整数の足し算を常に一定時間とみなせるわけではありません。ここで数えているのは足し算の回数です。

木全体を描くと指数的に多く見える仕事が、状態の種類で数えるとずっと少ない。この二つの数を区別するのが効率化の出発点です。とはいえ、ハノイのように実際の全移動を出力する仕事では、似た形をまとめても2ⁿ − 1回分の出力そのものは消せません。

Pythonコードを読む
from functools import cache

@cache
def fib(n):
    if n < 2:
        return n
    return fib(n - 1) + fib(n - 2)
ここに注目

この例の入力は0以上の整数。fib(4) = 3、fib(10) = 55。

7.3　まとめれば、いつでもDAGになるか

有向非巡回グラフ、DAGは、矢印に沿って進んでも同じ頂点へ戻る輪がない有向グラフです。フィボナッチでは辺をたどるごとにnが減るので、DAGになります。麻雀の残り牌も、面子を除くたびに枚数が減るため同様です。

しかし、どんな再帰でも状態をまとめればDAGになるわけではありません。迷路の通行可能性を位置だけでまとめれば輪が残ります。状態AがBを要求し、BがAを要求するなら、計算済みの結果だけを保存するメモ化では、最初の答えが一つも完成しないことがあります。

そのような問題では、計算中の印による循環検出や、問題に応じた別の解法が必要です。メモ化は停止性の証明の代わりにはなりません。また、引数が同じでも共有状態が変わる処理では、引数だけをキーにすると異なる問題を誤って統合するおそれがあります。

木からDAGへまとめた後も、実行中の復帰先が複数になって迷うわけではありません。いま結果を要求した具体的な呼び出しには、その呼び出し元があります。DAGが表すのは部分問題の共有であり、コールスタックが表す実行の入れ子とは別の関係だからです。

ハノイの状態グラフは逆向きにも移動でき、周期を持ちます。第3章の解法の呼び出し木は枚数が減り続けます。同じ題材から作った二つの図でも、非巡回性の理由はまったく違います。どの対象をノードにしたかを、ここでも先に確認しましょう。

ここに注目

DAGである理由を、図の見た目ではなく「減る量」や依存の順序で説明する。

7.4　深さから見るか、距離から見るか

DFSは、いま選んだ枝の先を優先します。幅優先探索、BFSは、入口から辺1本で届く頂点、その次は2本で届く頂点という順で調べます。前者ではスタック、後者では先に入れたものから取り出すキューが基本です。［3］

各辺の移動コストが同じなら、BFSで初めて到達したときの辺数は最小です。図2.1なら、SからDを1本で発見し、E、Gへと広げて3本の道を得ます。重みの違う辺では、この保証をそのまま使うことはできません。

DFSもBFSも、訪問済み管理と隣接リストを用いれば、有限グラフを調べる時間はO(V + E)です。Vは頂点数、Eは辺数。違いは主に調べる順序と途中で保持する境界の形です。どちらも最悪時にはO(V)の領域を使います。

この章のまとめ

呼び出しを数える木と、異なる部分問題を数えるDAGを区別する。重複を共有し、目的に合う探索順序を選ぶ。

RECURSION / ENDING

終章

再帰という木構造生成装置

迷路では隣を探し、ハノイでは小さい塔を移し、図形では縮小コピーを作り、麻雀では面子を除きました。問題固有の規則が子を生み、呼び出したという事実が親子関係を与えます。

「木構造生成装置」は、この働きに付けた本書の呼び名です。新しい数学的定理の名称ではありません。再帰をこの視点から見ると、分岐、復帰、深さ、仕事量、重複を一つの図で調べられます。

重要なのは、何でも木に見立てることではありません。何を1ノードとし、何を辺としたかを明示することです。それができれば、木の背後にあるグラフも、木に加わる幾何学も見えてきます。
