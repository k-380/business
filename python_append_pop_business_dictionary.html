第1章
倉庫に商品を入れる、取り出す

基本例＋発展例を独立実行 · 演習3問と解答 · 状態図付き

1　この章で解決する現場の問題

夕方、試作室に届いた箱を棚に載せ、翌朝、手前の箱から取り出す。帳票には箱の名前があるが、どの箱が残っているかが分からない。この章では「箱を1個ずつ管理する」小さな倉庫を作る。箱の中の部品数はまだ数えない。len()が返すのはリストの要素数であり、箱の中身の総数ではない。

2　人間が行う作業

人間なら、入れた箱をメモの末尾に書き、取り出した箱の行を消して出庫帳に転記する。ここでは棚の奥をリストの左、取り出し口を右とする。右端しか触れない棚を想定するから、最後に入れた箱が最初に出る。実際の棚がどこからでも取り出せるなら、この制約をまねる必要はない。

3　データ構造への置き換え

リストは、複数の値を順番付きで保持する入れ物である。stock = [] は空の入れ物を作り、その入れ物をstockという名前で参照する。文字列は引用符で囲む。stock.append("箱A") は末尾に1要素を追加する。Pythonのlistには標準のpush()はなく、スタックへ積む操作にはappend()を使う。

pop()は、末尾の要素を削除すると同時に、その値を呼び出し元へ返す。item = stock.pop() と書けば、取り出された箱の名前がitemに残る。これに対してstock[-1]は末尾を見るだけで、在庫数は変わらない。この差を「確認」と「実行」の差として理解しよう。

箱を文字列、在庫と出庫履歴を別々のリストにする。右端が取り出し口。箱数はlenで数える。

5　コードを業務の言葉で読む

最初の2行は在庫と履歴という別々のリストを準備する。3〜4行目の順で箱を積むため、右端は箱Bになる。5行目は参照なので箱数は2のまま。6行目で初めて箱Bを取り除き、7行目で出庫履歴へ追加する。最後の表示では、在庫と履歴の両方を見て、箱が消失していないことを確かめる。

append()の戻り値はNoneである。stock = stock.append("箱C") と書くと、stockはリストではなくNoneになる。「中身を変更する命令」と「新しい値を返す命令」を区別する必要がある。pop()は中身を変更し、さらに取り出した値を返す。

7　実務上の例外と改善

在庫が空のときpop()を呼ぶとIndexErrorになる。これはPythonの故障ではなく、取り出す対象がないという契約違反である。学習段階ではif stockで空かどうかを調べられる。ただし複数の作業者が同時に触る場合、確認と取り出しの間に別の人が取り出す可能性がある。並行処理は第30章で扱う。

昔のBASICでは、配列と件数変数を別々に用意し、追加時に件数を増やして配列へ代入する書き方がよく使われた。Pythonのリストは長さを内部で管理し、必要に応じて領域を拡張する。ただしBASICにも動的配列やコレクションを備える方言があり、「BASICには不可能だった」という意味ではない。

基本例＋発展例を独立実行 · 演習3問と解答 · 状態図付き

1　この章で解決する現場の問題

始発で10人が乗り、A停留所で3人、B停留所で4人、終点Cで3人が降りる。乗客の人数だけを引き算すると、誰が降りたかは分からない。ここでは乗客IDと降車地点を一緒に管理し、停留所ごとに車内の状態を更新する。乗客はすべて架空である。

2　人間が行う作業

        raise ValueError("対象箱がない")

        buffer.append(stock.pop())
        moves += 1

        stock.append(buffer.pop())
        moves += 1

1　この章で解決する現場の問題

CADで線を引き、位置を変え、寸法を入力した後、最後の入力だけ取り消したい。Excelやテキストエディタでも同じ操作をする。Undoは過去へ戻る機能、Redoは取り消した操作をもう一度適用する機能である。2つのスタックを使うと、その関係が明確になる。

2　人間が行う作業

人間が作業記録を積むと考えよう。実行済みの記録はUndo側へ積む。取り消すとUndoから1件取り出し、その記録をRedo側へ移す。やり直すと逆方向へ移す。新しい操作を行った場合は、それまでのRedoを消す。履歴が枝分かれするため、古い未来をそのまま再利用できないからである。

3　データ構造への置き換え

履歴の表現には大きく2通りある。状態全体を保存するスナップショット方式と、変更内容・逆操作を保存するコマンド方式である。前者は分かりやすいが容量を使う。後者は軽い場合があるが、逆操作が正しく定義できる必要がある。

最初の例は文字列の状態全体を保存する。文字列は変更不能な値なので、保存後に中身だけ書き換わる心配がない。リストや辞書を状態として保存するときは参照共有に注意する。

現在状態、Undoスタック、Redoスタックの3領域に分け、操作のたびに状態を移す。

7　実務上の例外と改善

Undo対象がリストの場合、undo_stack.append(state)は同じリストへの参照を積むだけである。その後state.append(...)すると過去も変わったように見える。平坦なリストならcopy()、入れ子の辞書まで切り離すならcopy.deepcopy()を検討する。ただしDB接続や外部ファイルまで過去に戻せるわけではない。

コマンド方式では、追加した値、削除した値、元の位置などを記録する。Undoする前に現在の状態が想定と一致するかを確認し、他の人が変更した状態へ古い逆操作を適用しない。末尾へ追加した操作なら、末尾がその対象であることが取消条件となる。

CADでは1回のドラッグを細かい座標更新100回として保存するか、1つの操作としてまとめるかも重要になる。操作の粒度が小さすぎるとUndoを何度も押す必要があり、大きすぎると必要な変更まで消える。スタックの実装だけでなく、ユーザーが考える1操作に合わせて設計する。

        self.undo_stack.append(("add", value))

        return True

実務設計ノート　履歴が満たすべき関係

現在をS、Undoの最上段をU、Redoの最上段をRとする。Undo可能なときは現在SをRedoへ積み、Uを現在へ移す。直後にRedoすれば、Sへ戻る。この往復関係をテストできる。何度戻しても空のスタックから取り出さないこと、新規操作でRedoが空になることも基本の不変条件である。

スナップショット方式では、状態の等しさを比較すれば復元を確認しやすい。コマンド方式では、各操作と逆操作の組が正しいかを検証する。たとえば位置iへの挿入の逆は位置iからの削除であり、値が同じものを探してremoveすることではない。

削除を取り消す場合は削除した値を保存していなければ復元できない。ファイル名だけを覚え、ファイル本体を完全に削除してしまった後でUndoを表示しても、元のデータは戻らない。履歴の見た目と復元能力を一致させる必要がある。

実務設計ノート　どこまでを1操作とするか

大量のセルへ貼り付ける処理を考えよう。1セルごとの更新を1000回のUndoにするより、貼り付け全体を1操作としてまとめる方が自然なことが多い。このまとまりの途中でエラーになったとき、全部取り消すか、一部成功を認めるかも合わせて決める。

履歴の保存数を100件に制限すると、101件目で最古の履歴を捨てることになる。取り消せる範囲が短くなるため、ユーザーへ分かる表示が望ましい。スナップショットは状態が大きいほど重くなるので、件数だけでなく容量上限も考える。

複数人が共同編集する環境で、自分のUndoが他の人の変更まで巻き戻すと危険である。本章の2スタックは単一編集者を前提にしている。共同編集では操作の変換、競合解決、版管理など別の仕組みが必要になる。

1　この章で解決する現場の問題

部品を出荷口へ運ぶ通路が枝分かれしている。まず到達できるか知りたいのか、通路数が最少の経路か、移動時間が最小の経路かで手法が違う。点を場所、線を移動可能な通路として表したものをグラフという。

2　人間が行う作業

深さ優先探索（DFS）は1つの道を奥まで進み、行き止まりなら戻る。スタックが向く。幅優先探索（BFS）は出発点から1歩、2歩と近い層を順に調べる。キューが向く。どちらも探索済みの場所を記録しないと、循環路を何度もたどってしまう。

DFSとBFSの経路を比較する

ch23_example1.py · Python 3
from collections import deque
graph = {"S": ["A", "B"], "A": ["C"], "C": ["G"],
         "B": ["G"], "G": []}

def search(breadth):
    waiting = deque([["S"]])
    seen = {"S"}
    while waiting:
        path = waiting.popleft() if breadth else waiting.pop()
        node = path[-1]
        if node == "G":
            return path
        neighbors = graph[node] if breadth else reversed(graph[node])
        for nxt in neighbors:
            if nxt not in seen:
                seen.add(nxt)
                waiting.append(path + [nxt])
    return None

print("DFS:", search(False))
print("BFS:", search(True))

7　実務上の例外と改善

    if cost != distance[node]:

        path.append(node)
        node = parent[node]
    path.reverse()

class Route:
    def __init__(self, state=None):
        self.state = state if state is not None else {
            "stops": ["A", "B", "C"], "next": 0, "capacity": 2,
            "onboard": [], "used_ids": [], "log": []}

    def visit(self, stop, incoming):
        s = self.state
        index = s["next"]
        if index >= len(s["stops"]) or s["stops"][index] != stop:
            raise ValueError("停留所の順序が不正")
        ids = [p["id"] for p in incoming]
        if len(set(ids)) != len(ids) or set(ids) & set(s["used_ids"]):
            raise ValueError("乗客ID重複")
        future = s["stops"][index + 1:]
        if any(not p["id"] or p["off"] not in future for p in incoming):
            raise ValueError("降車先またはIDが不正")
        departed = [p["id"] for p in s["onboard"] if p["off"] == stop]
        remaining = [p for p in s["onboard"] if p["off"] != stop]
        if len(remaining) + len(incoming) > s["capacity"]:
            raise ValueError("定員超過")
        s["onboard"] = remaining + [p.copy() for p in incoming]
        s["used_ids"].extend(ids)
        s["next"] += 1
        s["log"].append({"stop": stop, "off": departed, "on": ids})

失敗後を想像する

  • 壊れたファイルを見つけたら、黙って空データにせず停止できるか。

  • 入力や並べ替えなど事前作業を費用に含めたか。
  • 件数だけでなく、待ち時間・手戻り・誤処理を測れるか。

  • モデル外の作業が増え、担当者へ負担を転嫁していないか。
