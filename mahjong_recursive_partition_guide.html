アルゴリズム入門・実行例つき

麻雀の手牌をどう分割するか

順子・刻子・塔子の候補列挙から、再帰呼び出しとバックトラッキングによる全パターン探索まで。

完成面子を見つけることと、同時に成立する組み合わせを選ぶことは、別の問題である。

1. 何を計算したいのか

麻雀の手牌には複数の解釈がある。同じ牌を順子にするか刻子にするか、対子として残すかによって、全体の構造が変わる。したがって、候補を一つ見つけて確定するのではなく、複数の分割を比較したい。

基本方針：①候補を列挙する → ②同じ実物の牌を重複して使わない組み合わせを作る → ③各分割を評価する。なお②は、再帰探索で候補生成と同時に実行することもできる。

候補の種類

種類例成立条件
順子③④⑤同色の数牌が3連続
刻子⑦⑦⑦同種の牌が3枚
対子⑦⑦同種の牌が2枚
連続塔子③④同色の数牌が2連続。待ちの種類は位置次第
嵌張塔子③⑤同色の数牌が1つ飛び
孤立牌⑨他グループに使わず単独で残す

ここでの「分割」は評価用の抽象的なグループ化であり、必ずしも最終的な和了形とは限らない。

2. 候補を列挙するだけでは足りない

例えば萬子の 23456 からは、順子 234・345・456 をそれぞれ候補として取り出せる。しかし 234 と 345 は3萬と4萬を共有するので、所持牌が各1枚なら同時採用できない。

最初の候補列挙では重複を許してよい。ただし、完成した分割では各牌の使用枚数 ≤ 手牌内の所持枚数を守らなければならない。

関数 候補抽出(手牌):
    枚数 = 牌種ごとに数える
    候補 = []
    全牌種 t について:
        もし 枚数[t] ≥ 3: 刻子(t,t,t) を追加
        もし 枚数[t] ≥ 2: 対子(t,t) を追加
    各数牌の色 s と数字 n について:
        もし n ≤ 7 かつ n,n+1,n+2 が各1枚以上:
            順子(s:n,n+1,n+2) を追加
        もし n ≤ 8 かつ n,n+1 が各1枚以上:
            連続塔子(s:n,n+1) を追加
        もし n ≤ 7 かつ n,n+2 が各1枚以上:
            嵌張塔子(s:n,n+2) を追加
    戻す 候補

この処理は「牌種として作れる候補」の列挙。同じ形を2組以上取る多重度は、後の枚数管理で決まる。

3. 再帰探索という別解

先に全候補を作らなくてもよい。残り手牌から最小の牌を1枚選び、その牌を含む合法なグループの各候補を試す。一つ選んだら、そのグループを除いた残り手牌を同じ関数に渡す。

引数A：残り手牌

まだ使っていない牌。再帰が進むたびに減る。

引数B：現在の分割

すでに確定したグループの並び。

終了条件

残り手牌が空なら、その分割を結果一覧に保存する。

関数 探索(残り, 分割):
    もし 残り が空:
        結果に 分割 を保存
        戻る

    t = 残りの最小牌

    t を含む合法な各候補 g について:
        # 刻子・順子・対子・連続塔子・嵌張塔子
        # さらに孤立牌 [t] も必ず候補に含める
        次の残り = 残り から g の牌を取り除く
        探索(次の残り, 分割 + [g])

最小牌を含むグループだけを選ぶと、同じグループ群を選択順序だけ変えて何度も生成する無駄を抑えられる。なお通常の実装では萬子・筒子・索子をまたぐ順子は不可、字牌の順子も不可である。

4. 実行例：2223345 萬

左端の2萬をどのグループに使うかで、最初の枝が分かれる。

例えば次の2つの道筋はいずれも合法。

経路A

2223345 → 3345（刻子222）→ 45（対子33）→ 空（塔子45）

結果：222 / 33 / 45
経路B

2223345 → 2235（順子234）→ 35（対子22）→ 空（嵌張35）

結果：234 / 22 / 35

探索木はどう広がるか

探索(2223345, [])

│  │  ├─ 塔子45 → 探索(空, [222,33,45]) ★保存
│  │  └─ 孤立牌4 → さらに探索...
│  └─ 孤立牌3 → さらに探索...
├─ 順子234 → 探索(2235, [234])
│  ├─ 対子22 → 探索(35, [234,22])
│  │  └─ 嵌張35 → 探索(空, [234,22,35]) ★保存
│  └─ その他の分割...

└─ 孤立牌2 → 別の分割...

枝を1つ最後まで試し、戻って別の枝を試すことをバックトラッキングという。

5. 実際に全分割を列挙する

萬子だけの小さな手牌を入力し、実際の再帰探索で得られた結果を確認できる。牌は数字の連続（例：2223345）。

同一牌は4枚まで。列挙される分割には孤立牌も含めるため、これは標準形のシャンテン数そのものではない。大きな手牌では結果表示を先頭80件に制限する。

6. シャンテン数へ発展させる際の注意

単純に「面子数が多ければ良い」とは限らない。標準形では4面子＋雀頭という構成、最大4組までの塔子、雀頭として使う対子の区別などを考慮する。七対子・国士無双は別の評価ロジックが必要となる。

設計のコツ：候補生成・合法な分割探索・分割の評価を独立させる。そうすると、シャンテン数計算、受け入れ枚数計算、打牌比較へ段階的に発展させやすい。

検証のポイント

①各結果の牌を再結合すると元の手牌と一致すること。②1枚の牌を二重に使っていないこと。③同じ分割が順序違いで重複していないこと。④探索のすべての枝で残り牌の枚数が減り、必ず終了すること。
