CHAPTER 01

第1章　世界は点と線で表現できる

駅から駅へ移動する問題と、ある部品の変更がどの製品へ波及するかを調べる問題は、見た目が違います。しかし、対象を点、関係を線に置き換えると、どちらも「つながりをたどる」計算になります。グラフ理論は、この共通部分を取り出して扱う数学です。

この章の学習目標対象と関係を分離してモデル化し、有向・無向・重み付きという選択を説明できるようになります。

1.1 座標のグラフとは何が違うか

関数 y=f(x) のグラフは値と位置の対応を表します。本書のグラフは、対象間の関係を表します。点の座標や線の長さは、明示的に意味を与えなければデータではありません。路線図の線を曲げても、駅の接続が変わらなければ同じグラフです。

工学ではこの区別が重要です。配管の接続図は流体が通れる順序を表せますが、圧力損失を求めるには径、長さ、流量、局所抵抗なども必要です。「グラフにした」ことは、物理モデルが完成したことを意味しません。まず何を計算したいかを決め、その計算に必要な属性を残します。

1.2 頂点集合と辺集合

グラフを G=(V,E) と書きます。V は頂点の集合、E は辺の集合です。頂点数を N=|V|、辺数を M=|E| と表します。集合の要素数を表す縦棒 | | は絶対値とは用途が異なります。本書では特記しない限り、有限で、自己ループと多重辺のない単純グラフを扱います。

無向辺 {u,v} は順序を持ちません。有向辺 (u,v) は u から v への移動を表し、逆向きの移動を保証しません。SNSの相互の友人関係には無向グラフ、一方的なフォローには有向グラフが自然です。Pythonの組 (u,v) で無向辺を保存することもありますが、そのときは「順序を区別しない」という解釈を別途約束します。

無向：E ⊆ {{u,v} : u,v∈V, u≠v}　　有向：E ⊆ {(u,v) : u,v∈V, u≠v}

1.3 重みは何を意味するか

辺に数値を割り当てる関数 w:E→ℝ を重みと呼びます。所要時間、建設費、距離などが例です。最短経路では通過した辺の重みを加えることが多いですが、故障確率をそのまま足すのは一般に誤りです。重みの単位と合成規則は一緒に定義してください。

駅0、1、2の間に、0—1が4分、1—2が3分、0—2が10分という線路があるとします。0から2へ直接進むと10分、1を経由すると4+3=7分です。辺数の最小化と所要時間の最小化は違います。後者を解くには、重みを失わない表現が必要です。

1.4 抽象化の手順

最初に対象を列挙し、番号を割り当てます。次に「何が成立したとき辺を張るか」を一文で書きます。部品が接触する関係と、組立時に先に取り付ける必要がある関係は、同じ部品集合でも別のグラフです。方向、重み、時点も確定してからデータ化します。

グラフからは到達可能性、最短経路、連結成分、全体をつなぐ最小費用などを計算できます。一方、組織図の辺から人間の信頼まで読み取ることはできません。結論は、辺に与えた意味の範囲でのみ有効です。この姿勢は第18章の実務モデルに引き継ぎます。

アルゴリズムの見取り図

対象を番号化 → 関係を列挙 → 方向と重みを確定 → 各辺を隣接先へ登録

Pythonで確かめる

入力例はプログラム末尾に含まれます。全体をそのまま実行してください。

names = ["駅A", "駅B", "駅C"]
edges = [(0, 1, 4), (1, 2, 3), (0, 2, 10)]
adjacency = [[] for _ in names]
for u, v, minutes in edges:
    adjacency[u].append((v, minutes))
    adjacency[v].append((u, minutes))
print(adjacency)
print("経由:", edges[0][2] + edges[1][2])

実行結果

[[(1, 4), (2, 10)], [(0, 4), (2, 3)], [(1, 3), (0, 10)]]
経由: 7

計算量と前提

辺を1本ずつ登録する時間は O(N+M)、隣接リストの記憶量も O(N+M) です。無向辺を2回記録しても定数倍なので次数は変わりません。

第2章　グラフの基本的な性質

線を一本増やすと、頂点全体の次数の合計はいくつ増えるでしょうか。局所的に数えた接続数と、全体の辺数を結ぶ関係から始めます。歩き方の用語を区別すると、後の行列計算でも何を数えているか迷わなくなります。

この章の学習目標次数、歩道・小道・単純経路、閉路、連結成分を区別し、握手補題を証明します。

2.1 次数と握手補題

無向グラフで頂点vに接続する辺の本数を次数 deg(v) と呼びます。有向グラフでは、出ていく辺を出次数、入ってくる辺を入次数として分けます。孤立点の次数は0です。単純無向グラフでは最大次数はN−1ですが、多重辺を許すとこの上限は使えません。

Σv∈V deg(v)=2M

この式が握手補題です。各辺は異なる二つの端点を持ち、次数の合計にはちょうど2回寄与します。したがって全辺を数えれば2Mとなります。次数の合計が偶数なので、奇数次数の頂点の個数も偶数です。自己ループを許す流儀ではループを次数へ2回数える必要があります。本書の通常の例にはループを入れません。

2.2 歩道、小道、道

歩道（walk）は、隣り合う頂点が辺で結ばれた頂点列 v₀,v₁,…,vₖ です。長さは通った辺の回数kで、頂点数ではありません。辺も頂点も繰り返せます。小道（trail）は同じ辺を繰り返さない歩道、道または単純経路（path）は頂点を繰り返さない歩道です。「経路」という日本語だけでは文献間に揺れがあるため、本書では必要に応じて単純経路と明記します。

三角形0—1—2—0で、0,1,0,2は歩道ですが、無向辺0—1を往復するので小道ではありません。0,1,2,0は辺を繰り返さない閉じた小道ですが、始点0が再登場するので本書の単純経路ではありません。始点と終点だけが一致し、途中の頂点が異なる長さ3以上のものを、単純無向グラフの閉路と呼びます。0,1,0という往復は閉じた歩道ですが、閉路ではありません。

2.3 連結性と部分グラフ

任意の二頂点間に歩道が存在する無向グラフを連結と呼びます。歩道中の反復区間を取り除けば単純経路が得られるため、「単純経路が存在する」と言い換えても同じです。互いに到達できる頂点をまとめた最大の集合が連結成分です。孤立点も一つの連結成分になります。

部分グラフH=(W,F)はW⊆V、F⊆Eで、Fの両端がWに含まれるものです。W内の頂点間にある元の辺をすべて残す場合は誘導部分グラフです。辺を好きに間引いた部分グラフと区別してください。有向グラフの「連結」は、方向を無視した弱連結と、全ての組について双方向に到達可能な強連結を区別します。

2.4 手計算で検算する

頂点0,1,2が三角形を作り、頂点3を孤立させます。次数列は(2,2,2,0)、次数和は6、辺数は3です。連結成分は{0,1,2}と{3}の二つです。辺が3=N−1本あるにもかかわらず木ではありません。この反例は第7章の判定条件で再登場します。

アルゴリズムの見取り図

次数配列を0で初期化 → 各無向辺の両端を1増加 → 合計と2Mを照合

Pythonで確かめる

入力例はプログラム末尾に含まれます。全体をそのまま実行してください。

n = 4
edges = [(0, 1), (1, 2), (2, 0)]
degree = [0] * n
for u, v in edges:
    degree[u] += 1
    degree[v] += 1
print(degree)
print(sum(degree), 2 * len(edges))
assert sum(degree) == 2 * len(edges)

実行結果

[2, 2, 2, 0]
6 6

計算量と前提

次数集計は時間O(N+M)、追加空間O(N)です。頂点列が歩道か調べる費用は辺検索の表現によります。隣接集合を用いれば平均O(k)で長さkの列を照合できます。

第3章　グラフをコンピュータに記憶させる

部品が10万個あるのに、関係は各部品につき数個しかないとします。10万×10万の表を先に確保する必要はあるでしょうか。何を速く調べたいかによって、適切なデータ構造は変わります。

この章の学習目標辺リスト・隣接リスト・隣接行列を相互に変換し、疎なグラフと密なグラフの違いを説明します。

3.1 三つの表現

辺リストは(0,1),(0,2),(1,3),(1,4)のように辺を並べます。全辺を一度ずつ処理するときに便利で、辺の重み順に並べ替えるKruskal法で活躍します。ただし「頂点1の隣は誰か」を毎回探すには、全辺を見る素朴な方法でO(M)かかります。

隣接リストは頂点ごとに隣をまとめます。この例の頂点1なら[0,3,4]です。無向辺を両方向に保存するので、全リストの要素数は2Mです。有向グラフなら出辺だけを記録してMとなります。リストの順番は数学的な接続関係に影響しませんが、探索で同順位の候補をどちらから訪問するかに影響します。

隣接行列はN行N列の表で、辺がある位置を1、ない位置を0にします。無向の場合A[u][v]とA[v][u]を両方1にします。辺の存在照会はO(1)ですが、隣接頂点の列挙には行全体のO(N)の走査が必要です。

表現容量辺u→vの照会uの隣の列挙
辺リストO(N+M)※O(M)O(M)
隣接リストO(N+M)O(deg(u))O(deg(u))
隣接行列O(N²)O(1)O(N)

※辺だけならO(M)ですが、孤立点を含む頂点情報も保存する場合の容量を示しています。ハッシュ集合による隣接表なら存在照会は平均O(1)にできますが、順序やメモリの性質が変わります。

3.2 同じものを共有しない初期化

Pythonで [[]] * n とすると、同じ内側のリストをn回参照します。一つにappendすると、すべての行が変わったように見えます。[[] for _ in range(n)] と書いて独立したリストを作ってください。行列も [[0] * n for _ in range(n)] とします。

無向辺を両方向に追加した後、さらに逆向きの辺を入力すると、重複が生まれます。本書の入力は各無向辺を一度だけ記録する約束です。重複入力を拒否するか多重辺として扱うかも、プログラムの仕様に含めます。頂点番号は全章で0からN−1です。

3.3 大きさから表現を選ぶ

疎なグラフは、可能な辺数に比べて実際の辺が少ないグラフです。無向単純グラフの最大辺数はN(N−1)/2なので、Nが大きいとO(N²)は急激に増えます。木ではM=N−1であり、隣接リストが特に適しています。

行列が劣るという意味ではありません。全ての頂点対を扱う計算や線形代数への接続には行列が自然です。Pythonの整数オブジェクトとNumPyの固定長配列では実メモリも異なります。O記法は規模に対する増え方であって、バイト数そのものではありません。

    adjacency[u].append(v)
    adjacency[v].append(u)
    matrix[u][v] = matrix[v][u] = 1

    print(row)

第4章　グラフの中を歩く

全駅を通る旅と、全線路を通る点検は同じ問題でしょうか。どちらも「全部回る」ように聞こえますが、使い切る対象が頂点か辺かによって計算の難しさは大きく違います。

この章の学習目標到達可能性と距離を定義し、オイラー路とハミルトン路の条件・難しさを区別します。

4.1 距離と最短経路

無重みグラフの距離d(u,v)は、uからvへの歩道のうち最小の辺数です。到達不能なら∞とします。d(u,u)=0です。最短歩道が頂点を反復していたら、その反復の間を削って短くできるため、最短歩道は単純経路になります。無向グラフでは距離は対称ですが、有向グラフではd(u,v)とd(v,u)は違う場合があります。

重み付きの場合は辺数の代わりに重みの和を最小化します。ただし負の閉路を何度も回れると、歩道の重みを無限に下げられます。「最短経路」という名称だけで条件を省略せず、負の重みを扱うときは第14章の前提を確かめてください。

4.2 オイラー路：辺を使い切る

全ての辺をちょうど一度ずつ通る小道をオイラー路と呼びます。閉じていればオイラー閉路です。辺を持つ無向グラフで、孤立点を除いた部分が連結であるとき、オイラー閉路が存在する必要十分条件は全頂点の次数が偶数であることです。閉じないオイラー路は奇数次数の頂点がちょうど2個のとき存在します。

必要性は出入りを対にすることで分かります。途中の頂点は入る辺と出る辺を組にでき、両端だけが1本余ります。十分性は、未使用辺をたどって小道を作り、残った辺があれば途中の頂点から別の閉じた小道を挿し込む構成で証明できます。これがHierholzer法の基礎です。奇数次数が2個なら両端を仮の辺でつなぎ、閉路を作ってからその辺を取り除きます。

4.3 ハミルトン路：頂点を使い切る

全頂点をちょうど一度ずつ通る単純経路がハミルトン路です。一般のグラフでは、次数の偶奇だけで存在を判断できません。中心と3枚の葉を持つ星では、どの葉から始めても、中心を通った後は別の葉で行き止まりになり、3枚目へ進めません。

頂点の並びを全て試す方法はN!通りを検査します。ハミルトン路の存在判定は一般にNP完全です。これは「どんな入力でも必ず指数時間が必要」と証明されたという意味ではなく、多項式時間で常に解ける方法が知られておらず、存在すればP=NPを導く問題だという位置づけです。木や小さい入力など、構造を制限すれば別の解き方があります。

4.4 小規模な全探索から学ぶ

本章の実装は頂点数を小さく限定し、全順列を列挙して隣り合う頂点に辺があるかを確認します。三角形では最初の候補(0,1,2)が成功します。高速とはいえませんが、何を答えと認めるかを直接コードにした検証用の基準になります。後で高速な方法を作る際にも、小規模入力に対する全探索は有用です。

アルゴリズムの見取り図

Pythonで確かめる

from itertools import permutations

def hamiltonian_path(n, edges):
    neighbors = [set() for _ in range(n)]
    for u, v in edges:
        neighbors[u].add(v)
        neighbors[v].add(u)
    for order in permutations(range(n)):
        if all(order[i + 1] in neighbors[order[i]]
               for i in range(n - 1)):
            return order
    return None

print(hamiltonian_path(3, [(0, 1), (1, 2), (2, 0)]))
print(hamiltonian_path(4, [(0, 1), (0, 2), (0, 3)]))

実行結果

None

第5章　木構造とは何か

一本道の連絡経路をどこかで切ると、その先へ届かなくなります。一方、輪になったネットワークなら迂回できます。木は、全体がつながっている一方で、迂回の余裕を持たないグラフです。

この章の学習目標木と森を定義し、経路の一意性、辺数、辺を除く効果を証明します。

5.1 連結で閉路がない

木とは、連結かつ閉路を持たない有限の単純無向グラフです。本書ではN≥1とし、頂点1個で辺0本のグラフも木に含めます。N=0の空グラフは木とはしません。閉路を持たないグラフ全体を森と呼び、その各連結成分は木です。

木は上から下に描くものでも、二つずつ枝分かれするものでもありません。描き方は自由で、次数が何本でも構いません。木を階層として扱うための根は、次章で追加する情報です。閉路がないという条件は、紙の上で線が交差しないという条件とも違います。交点に頂点を置かなければ、線が交差しても接続したことにはなりません。

5.2 任意の二頂点を結ぶ単純経路は一つ

連結なので少なくとも一つの単純経路が存在します。もし異なる二つの単純経路があれば、両者が分岐する頂点から再び合流する最初の頂点までを合わせると閉路ができます。これは木の定義に反します。したがって単純経路はただ一つです。

逆に任意の異なる二頂点間に単純経路がただ一つあるなら連結です。もし閉路があれば、その閉路上の二頂点を時計回りと反時計回りの二通りで結べますから矛盾です。N=1でも連結かつ閉路なしなので整合します。単に「経路は一つ」と言うと往復を含む歩道まで排除してしまうので、単純経路という限定が重要です。

5.3 葉を取り除いて辺数を数える

N≥2の木には次数1の頂点、すなわち葉が少なくとも2個あります。最長の単純経路を取り、その両端を考えます。端点に経路外の隣接頂点があれば延長でき、経路内の別の頂点への辺があれば閉路になります。どちらも不可能なので両端の次数は1です。

葉と接続辺を1本取り除いても、残った頂点同士の単純経路は失われず、閉路も新しく生まれません。N=1で辺数0を基底とし、葉を一つずつ除く帰納法により、木の辺数はN−1です。森にc個の連結成分があれば、各成分の辺数を足してM=N−cとなります。

木：M=N−1　　森：M=N−c

5.4 辺の追加と除去

木の辺e={u,v}を除くと、uとvの間の唯一の経路が失われ、ちょうど2成分になります。もともと辺eを使わずuへ行ける側とvへ行ける側に分かれるため、3成分以上にはなりません。このような、除くと連結成分を増やす辺を橋と呼びます。木の辺は全て橋です。

逆に非隣接の二頂点を新しい辺で結ぶと、元の一意な単純経路と新しい辺がただ一つの閉路を作ります。通信網で冗長経路を追加することは、木から一般のグラフへ踏み出す操作です。辺が少ないことと障害に強いことは同じではありません。

第6章　木の根はどこにあるのか

同じ配線網を、電源側から見れば分岐図、末端の装置から見れば合流図として描けます。木の接続自体と、それを見る出発点は別の情報です。任意の頂点を根にできることは、単なる描画上の自由ではありません。

この章の学習目標根付き木の親・子・深さ・部分木を定義し、根による変化と不変量を分けます。

6.1 根を指定すると関係が生まれる

根なし木Tに一つの頂点rを指定した組(T,r)を根付き木と呼びます。r以外の頂点vの親は、vからrへの一意な単純経路でvの次に来る頂点です。親がvである頂点をvの子と呼びます。深さdepth(v)はrからvまでの辺数です。根の親は本書のコードでは−1とします。

根からvへの経路上の頂点をvの祖先と呼びます。自分自身を祖先に含める流儀を採用します。vを祖先に持つ頂点全体がvの子孫で、その頂点集合が誘導する木がvを根とする部分木です。部分木にはv自身を含めます。親子関係は元の木に最初から付いていたものではなく、根と接続から導かれるものです。

6.2 根0と根3を比べる

共通の木Tでは、根0の親配列は(−1,0,0,1,1)、深さは(0,1,1,2,2)です。根を3へ変えると親配列は(1,3,0,−1,1)、深さは(2,1,3,0,2)になります。頂点1は根0では0の子ですが、根3では0の親です。

根の移動が隣接頂点間なら、その一辺だけ親子の向きが逆転します。離れた頂点へ根を移すと、旧根と新根を結ぶ単純経路上の向きが逆転し、それ以外の辺の親子方向は変わりません。一方、深さは経路外の頂点でも変わりえます。「方向が変わる範囲」と「距離の値が変わる範囲」を区別しましょう。

6.3 保存されるもの、変わるもの

元の無向辺集合、次数、二頂点間の距離、木の直径は根を変えても不変です。根、親子、深さ、部分木の大きさ、最小共通祖先は変わりえます。無向木の葉を次数1と定義する場合、その集合は不変です。一方、根付き木で子を持たない頂点を葉と呼ぶ場合には根の選択が影響します。

根0での距離の総和は0+1+1+2+2=6、根3なら2+1+3+0+2=8です。個別の二頂点間距離は不変でも、「指定した根から全頂点への距離の合計」は根によって違います。この関数を全ての根について効率的に求めるのが全方位木DPの代表例です。

6.4 探索で階層を作る

根をスタックに入れ、取り出した頂点の未訪問の隣を子にします。木なので、一度親が決まった頂点に別の親候補が現れることはありません。一般グラフで同じ操作をすると探索木はできますが、元の全辺を親子辺として表せるわけではありません。閉路を含む関係を黙って木に置き換えないことが重要です。

def root_tree(adj, root):
    parent = [-2] * len(adj)
    depth = [0] * len(adj)
    parent[root] = -1
    stack = [root]
    while stack:
        u = stack.pop()
        for v in adj[u]:
            if parent[v] == -2:
                parent[v] = u
                depth[v] = depth[u] + 1
                stack.append(v)
    return parent, depth

adj = [[1, 2], [0, 3, 4], [0], [1], [1]]
for root in [0, 3]:
    print(root, root_tree(adj, root))

第7章　与えられたグラフは木なのか

辺数を数えたらN−1だった。それだけで「木です」と言ってよいでしょうか。三角形と孤立点を合わせるとN=4、M=3ですが、閉路があり、つながってもいません。必要条件を十分条件と取り違えない検査を作ります。

この章の学習目標木の同値条件を証明し、DFSとUnion-Findで正しく判定します。

7.1 同値な四つの条件

N≥1の有限単純無向グラフについて、次の条件は同値です。(A)連結かつ閉路なし、(B)連結かつM=N−1、(C)閉路なしかつM=N−1、(D)任意の異なる二頂点間に単純経路がただ一つ存在する、です。第5章で(A)⇒(B)と(A)⇔(D)は示しました。

(B)⇒(A)を示します。連結グラフを探索して、初めて到達した各頂点へ至る辺だけを残すと、根以外に一本ずつ、合計N−1本の辺が残ります。これらは全頂点をつなぎ、発見順の逆向きに親をたどれば根へ戻るため閉路がありません。元の辺もN−1本しかないので、余分な辺は存在せず元のグラフも木です。

(C)⇒(A)は森の公式M=N−cから得られます。N−1=N−cなのでc=1、したがって連結です。残りの(A)⇒(C)は木の辺数の公式です。証明に使った前提は有限・無向・単純・N≥1であり、有向グラフへそのまま移すことはできません。

7.2 DFSによる判定

辺数がN−1かを確認し、頂点0から全頂点を訪問できるかを調べれば(B)を検査できます。あるいは探索中に閉路を検出して(A)を直接調べることもできます。無向グラフでは親へ戻る辺を閉路と誤認しないよう、親を覚えておきます。

多重辺を許す場合、「相手が親なら全部無視」では不十分です。平行な二辺の片方だけが親辺で、もう片方は長さ2の閉路を作るからです。辺IDを保存して直前に使った一本だけを除外する方法もあります。本章は単純グラフを対象にし、前処理で自己ループと重複辺を拒否します。

7.3 Union-Findによる判定

Union-Findは、頂点がどの連結成分に属するかを管理します。最初は全頂点が別々です。辺(u,v)を追加するとき、両端が既に同じ成分なら、そこには既存の単純経路があり、新しい辺で閉路ができます。異なる成分なら二つを統合します。最後に成分が一つなら木です。

findは代表元を求め、unionは成分を結合します。代表元は木の数学的な根とは別の、データ構造上の管理番号です。小さい集合を大きい集合の下へつなぐサイズ併合と、探索時に親を代表へ近づける経路圧縮を組み合わせると、ほぼ定数時間で扱えます。厳密には一連の操作に対して逆Ackermann関数α(N)が現れます。

アルゴリズムの見取り図

DFS方式：辺数検査→到達頂点数検査。Union-Find方式：同じ成分への辺なら拒否→統合→最後の成分数を検査

def normalize(n, edges):
    if n < 1:
        return None
    seen = set()
    for u, v in edges:
        if not (0 <= u < n and 0 <= v < n) or u == v:
            return None
        key = (min(u, v), max(u, v))
        if key in seen:
            return None
        seen.add(key)
    return seen

def is_tree_dfs(n, edges):
    edges = normalize(n, edges)
    if edges is None or len(edges) != n - 1:
        return False
    adj = [[] for _ in range(n)]
    for u, v in edges:
        adj[u].append(v)
        adj[v].append(u)
    seen = {0}
    stack = [0]
    while stack:
        u = stack.pop()
        for v in adj[u]:
            if v not in seen:
                seen.add(v)
                stack.append(v)
    return len(seen) == n

class UnionFind:
    def __init__(self, n):
        self.parent = list(range(n))
        self.size = [1] * n

    def find(self, x):
        while self.parent[x] != x:
            self.parent[x] = self.parent[self.parent[x]]
            x = self.parent[x]
        return x

    def union(self, a, b):
        a, b = self.find(a), self.find(b)
        if a == b:
            return False
        if self.size[a] < self.size[b]:
            a, b = b, a
        self.parent[b] = a
        self.size[a] += self.size[b]
        return True

def is_tree_union_find(n, edges):
    edges = normalize(n, edges)
    if edges is None:
        return False
    uf = UnionFind(n)
    components = n
    for u, v in edges:
        if not uf.union(u, v):
            return False
        components -= 1
    return components == 1

for n, edges in [(1, []), (4, [(0,1),(1,2),(2,0)]),
                 (5, [(0,1),(0,2),(1,3),(1,4)])]:
    print(is_tree_dfs(n, edges), is_tree_union_find(n, edges))

第8章　木構造と再帰

ある部品ユニットに何個の部品が含まれるかは、子ユニットの部品数が分かれば計算できます。「同じ問題を、小さな構造に対して解く」という形が、根付き木と再帰を結びます。

この章の学習目標再帰の停止条件と処理順序を理解し、部分木サイズを再帰版・反復版で計算します。

8.1 部分木も根付き木である

根付き木の頂点vを取り出すと、その下には子を根とするいくつかの部分木があります。それらは互いに頂点を共有しません。部分木サイズs(v)をv自身を含む頂点数とすれば、子のサイズを足して1を加えればよいと分かります。DAGでは子の先で同じ頂点を共有する可能性があるので、この数え方がそのまま異なる頂点数になるとは限りません。

s(v)=1+Σu：vの子s(u)

8.2 再帰の基底と帰納的な正しさ

葉には子がないため、空の和を0とするとs(v)=1です。子の部分木サイズが正しいと仮定すれば、それらは互いに重ならず、vの部分木はv自身と子の部分木の合併なので上式も正しいです。葉から一段ずつ上へこの論理を繰り返すことで、全頂点で正しいと分かります。これを木の構造に関する帰納法と考えられます。

再帰関数は「自分と同じ関数を呼ぶ」だけでは成立しません。より小さい部分木へ進むことと、葉で停止することが必要です。親を除外せず無向辺を往復すると停止しません。また一般グラフでは親以外の既訪問頂点へ回り込めるため、訪問管理が必要です。

8.3 行きがけと帰りがけ

行きがけ順では子へ進む前に頂点を処理します。深さや根からの累積距離のように、親から子へ渡す情報に適します。帰りがけ順では子を全て処理してから頂点を処理します。部分木サイズや子の最適値を集約する木DPに適します。

共通の木Tを根0とし、子を番号順にたどると行きがけは0,1,3,4,2、帰りがけは3,4,1,2,0です。サイズは葉2,3,4が1、頂点1が1+1+1=3、根0が1+3+1=5です。計算順序が依存関係を満たしていることを確認してください。

8.4 再帰を明示的な順序へ置き換える

Pythonの再帰には深さ制限があります。頂点が一直線に並ぶ木では呼出しの深さがNになり、数千頂点でも失敗しえます。上限を無制限に増やすより、親が子より前に現れる順序をスタックで作り、その逆順でサイズを集約する方が堅実です。

逆順は厳密な再帰の帰りがけ順と同じでなくても構いません。必要なのは「全ての子が親より先に処理される」という依存条件です。以下は同じ入力に再帰版と反復版を適用して結果を比較します。再帰版は仕組みの理解用、反復版は深い木にも対応する実装です。

アルゴリズムの見取り図

def recursive_sizes(adj, root):
    sizes = [0] * len(adj)
    def visit(u, parent):
        sizes[u] = 1
        for v in adj[u]:
            if v != parent:
                visit(v, u)
                sizes[u] += sizes[v]
    visit(root, -1)
    return sizes

def iterative_sizes(adj, root):
    parent = [-2] * len(adj)
    parent[root] = -1
    order = []
    stack = [root]
    while stack:
        u = stack.pop()
        order.append(u)
        for v in adj[u]:
            if parent[v] == -2:
                parent[v] = u
                stack.append(v)
    sizes = [1] * len(adj)
    for u in reversed(order):
        if parent[u] != -1:
            sizes[parent[u]] += sizes[u]
    return sizes

adj = [[1,2], [0,3,4], [0], [1], [1]]
a = recursive_sizes(adj, 0)
b = iterative_sizes(adj, 0)
print(a)
print(b)
assert a == b

[5, 3, 1, 1, 1]

第9章　隣接行列の仕組み

グラフを表にすると、行や列の足し算に接続の意味を持たせられます。ここからは、頂点番号が表のどこに対応するかを固定し、図と数値の間を往復します。

この章の学習目標隣接行列の行・列の意味、対称性、次数との関係を理解し、NumPyで構築します。

9.1 行を出発点、列を到着点にする

頂点を0,1,…,N−1と並べ、Aのi行j列をAᵢⱼと書きます。辺i→jがあれば1、なければ0にします。無向グラフでは辺{i,j}について両方の成分を1にします。自己ループを持たないので対角成分は0です。頂点の並べ方を変えると行列の見た目も変わりますが、対応する行と列を一緒に入れ替えれば、同じグラフを表せます。

有向グラフの行の和は出次数、列の和は入次数です。無向グラフではA=Aᵀ、つまり転置しても同じ対称行列となり、行和も列和も次数です。一般には対称行列だから木なのではありません。三角形の隣接行列も対称です。

9.2 ベクトルとの積を読む

各頂点に数値xⱼがあるとします。通常の行列積y=Axでは、yᵢ=Σⱼ Aᵢⱼxⱼです。これは頂点iから出ていける隣の数値を集計しています。有向辺に沿って「現在地の量を次へ配る」なら、量を列ベクトルで表す規約ではAᵀxを使います。行ベクトルで量を表すならxAです。規約の取り違えは方向の逆転を招きます。

0→1、1→2、0→2があるとき、Aの行和は(2,1,0)、列和は(0,1,2)です。列ベクトルx=(10,20,30)ᵀに対してAx=(50,30,0)ᵀとなります。これは0の隣の20と30を足した値です。量の転送と隣の集計を、同じ積だと思わないようにしましょう。

9.3 NumPyの配列と演算

NumPyでは二次元配列をnp.arrayで作り、行列積は @ で計算します。* は同じ位置同士の要素積なので、隣接行列の歩道計算に使う演算とは異なります。sum(axis=1)は列方向に足して各行の和、sum(axis=0)は行方向に足して各列の和を返します。

辺の有無を表す0と、距離行列で「重み0の辺がある」ことは別です。重み付き最短経路用の行列で辺の不存在を0にすると、無料で移動できると誤解されます。その場合は∞などを用います。辺の本数を値にする多重グラフや、重みを成分に入れる行列にも拡張できますが、累乗が何を表すかは値の意味によって変わります。

第10章　なぜ行列の2乗が歩道を表すのか

行列を2乗すると、なぜグラフの中を2歩進んだ回数が出てくるのでしょうか。答えは、積の和が「途中でどの頂点を経由したか」による場合分けになっているからです。

この章の学習目標行列積を中継点による分解として読み、Aᵏが長さkの歩道を数えることを帰納法で証明します。

10.1 2歩を中継点で分類する

三角形の隣接行列は、対角が0、それ以外が1です。0から0へ2歩で戻るには0→1→0と0→2→0の2通りがあります。0から1へ2歩で行くには0→2→1の1通りしかありません。0→1の1歩の移動は、長さが違うため数えません。

(A²)₀₀=A₀₀A₀₀+A₀₁A₁₀+A₀₂A₂₀=0·0+1·1+1·1=2
(A²)₀₁=A₀₀A₀₁+A₀₁A₁₁+A₀₂A₂₁=0·1+1·0+1·1=1

積AᵢᵣAᵣⱼは、i→rとr→jの両方が存在する場合だけ1になります。全ての中継点rについて足すと、長さ2の全歩道をちょうど一度ずつ数えます。この意味で、行列積は「つなげるために掛け、場合分けをまとめるために足す」演算です。

10.2 k歩への一般化と証明

k=0ではA⁰=Iとします。長さ0の歩道は各頂点から自分自身への一通りだけなので、単位行列Iの対角1と一致します。k=1では隣接行列の定義そのものです。k歩について成立すると仮定して、k+1歩の最後の一辺の直前をrとします。

(Ak+1)ᵢⱼ=Σr=0N−1(Aᵏ)ᵢᵣ Aᵣⱼ

iからrへのk歩の歩道一つと、rからjへの辺一つを組み合わせるとk+1歩の歩道になります。逆にどのk+1歩の歩道も最後の辺で一意に分解できます。よって重複も漏れもなく数えられ、帰納法で全ての非負整数kについて成立します。有向グラフでも方向に従えば同じ証明です。

10.3 対角成分と閉じた歩道

(Aᵏ)ᵢᵢは頂点iへ戻る長さkの歩道数です。三角形でA²の対角が2であることは、長さ2の閉路が二つあるという意味ではありません。同じ無向辺の往復です。三角形ではA³の対角は各2で、三つの始点と二つの向きの合計6通りの閉じた歩道があります。

単純無向グラフの三角形数はtr(A³)/6です。trは対角成分の和です。ただし「長さkの閉路数はtr(Aᵏ)/(2k)」と一般化してはいけません。k=4では0→1→0→1→0のような反復歩道が入り、単純閉路以外を数えるからです。

10.4 実装と整数の大きさ

素朴にk回行列を掛ければO(kN³)です。指数を二進数で分解する繰り返し二乗法ならO(N³ log k)回程度の算術操作で済みます。本章はまず二重・三重ループで積の定義をそのまま実装します。Pythonの整数は任意精度なので固定長整数のあふれはありませんが、桁数の増大に伴い一回の演算自体が重くなる点には注意してください。

NumPyで通常の整数配列を使う場合は大きなkでオーバーフローすることがあります。厳密な個数が必要ならdtype=objectなどを検討します。重み付き行列の累乗は一般に「歩道上の重みの積を全歩道について足した値」です。重みが1でない限り、そのまま歩道の個数にはなりません。

アルゴリズムの見取り図

単位行列から開始 → 指数の下位ビットが1なら結果に掛ける → 基底を二乗 → 指数を半分にする

Pythonで確かめる

def multiply(A, B):
    n = len(A)
    return [[sum(A[i][r] * B[r][j] for r in range(n))
             for j in range(n)] for i in range(n)]

def matrix_power(A, k):
    if k < 0:
        raise ValueError("k must be nonnegative")
    n = len(A)
    result = [[int(i == j) for j in range(n)] for i in range(n)]
    base = [row[:] for row in A]
    while k:
        if k % 2:
            result = multiply(result, base)
        base = multiply(base, base)
        k //= 2
    return result

A = [[0,1,1], [1,0,1], [1,1,0]]
for k in [0, 2, 3]:
    print(k, matrix_power(A, k))
assert matrix_power(A, 2)[0][0] == 2

第11章　行列によるグラフ解析

つながりの情報を行列に入れると、辺を一つずつたどらずに、連結成分の数や全域木の本数を調べられます。ただし数値計算で得た「ほぼ0」と、数学的な0は分けて考えます。

この章の学習目標次数行列・ラプラシアン・零固有値・行列木定理を結び、三角形で計算します。

11.0 この章で使う線形代数の言葉

ベクトルは頂点ごとの数値を並べたもの、行列はその値をまとめて変換する表と考えます。Ax=0を満たすベクトルxの集合を零空間と呼びます。ここで0は全成分0のベクトルです。行列の階数は、列ベクトルのうち互いの線形結合では作れない独立な列の最大本数です。N列の行列では「階数＋零空間の次元=N」という階数・退化次数の関係があります。次元とは、その空間の全要素を線形結合で表すのに必要な独立な方向の数です。

0でないベクトルxについてLx=λxとなるとき、λを固有値、xを固有ベクトルと呼びます。変換しても向きが変わらず倍率だけが変わる方向です。λ=0の固有ベクトルは零空間に属します。実対称行列は直交する固有ベクトルの基底を持つというスペクトル定理を本章では用い、その一般証明は線形代数の教科書に譲ります。

行列式detは正方行列に割り当てる数で、二次元なら[[a,b],[c,d]]に対してad−bcです。独立な列が不足する行列の行列式は0になります。転置xᵀは縦に並べたベクトルを横に並べ直す記号で、xᵀLxは一つの数になります。これらの語を使っても、まず三角形の具体値へ戻って意味を確かめれば読み進められます。

11.1 ラプラシアンを作る

本章は無重みの有限単純無向グラフを扱います。次数行列DはDᵢᵢ=deg(i)、それ以外を0とする対角行列です。グラフラプラシアンをL=D−Aと定義します。三角形なら対角2、非対角−1です。各行の和は0なので、全成分が1のベクトルをLへ掛けると0になります。

L=D−A　　xᵀLx=Σ{u,v}∈E(xᵤ−xᵥ)² ≥ 0

右の恒等式は、xᵀDx=Σᵥdeg(v)xᵥ²と、xᵀAx=2Σ{u,v}xᵤxᵥを引けば得られます。一辺についてxᵤ²−2xᵤxᵥ+xᵥ²が残るので平方になります。隣接頂点の値が違うほど大きくなる量と読めます。物理的なばねや電気回路に似た形が現れますが、物性を与えない本章のLは純粋な接続の行列です。

11.2 零空間から連結性を読む

Lx=0ならxᵀLx=0です。非負の平方の和が0なので、全辺でxᵤ=xᵥとなります。経路でつながる頂点へ順に伝えれば、xは各連結成分内で一定です。逆に各成分で一定のベクトルなら各行の差が打ち消し合いLx=0です。

したがってLの零空間の次元は連結成分数cに等しく、階数はN−cです。Lは実対称行列なので固有値は実数で、平方和の式から全て非負です。0の固有値の重複度はcです。N≥2なら、固有値を小さい順にλ₁≤λ₂≤…と並べたとき、連結であることとλ₂>0であることは同値です。ここで使っているのはAではなくLです。

11.3 行列木定理

全域木は、元のグラフの全頂点を含む部分グラフで、それ自体が木であるものです。ラプラシアンLの同じ番号の行と列を一つずつ除いた(N−1)次正方行列をL⁽ʳ⁾と書くと、全域木の本数τ(G)はdet L⁽ʳ⁾に等しくなります。これは行列木定理です。非連結なら本数は0で余因子も0です。N=1の場合は0次行列の行列式を1と定め、一本の自明な全域木を数えます。

τ(G)=det L⁽ʳ⁾　　三角形：det [[2,−1],[−1,2]]=2·2−(−1)(−1)=3

証明の骨格を示します。各無向辺に便宜的な向きを付け、列に始点+1・終点−1を持つ接続行列Bを作るとL=BBᵀです。一行除いたBをBᵣとします。Cauchy–Binet公式によりdet(BᵣBᵣᵀ)は、N−1本の辺を選ぶ全ての集合Sについてdet(Bᵣ,S)²を足したものです。Sが閉路を含むと列が一次従属なので0です。N−1本で閉路なしなら全域木であり、葉の行または列から順に展開して行列式の絶対値が1と分かります。ゆえに各全域木が1だけ寄与します。公式そのものの一般証明は線形代数の範囲ですが、なぜ木だけが残るかはこの説明で確認できます。

11.4 数値計算の意味と限界

三角形では固有値は0,3,3、階数は2です。浮動小数点計算では0が10⁻¹⁶程度の数になる場合があるため、許容誤差を明示します。大きなグラフの連結判定をしたいだけならDFSの方が速く、丸め誤差もありません。行列式から巨大な整数を正確に求めたい場合も、浮動小数点の丸めだけでは保証になりません。本章の2×2行列式はPythonの整数で正確に求めます。

アルゴリズムの見取り図

Aから次数を求めDを作る → L=D−A → 固有値・階数を計算 → 同一番号の行列を除き余因子を求める

c, d = minor[1]
count = a * d - b * c
print("固有値:", np.round(values, 8).tolist())
print("階数:", np.linalg.matrix_rank(L))

assert count == 3

第12章　行列でネットワークを計算する

歩道の個数が欲しいとは限りません。行けるかどうかだけ知りたい場合や、最小費用を知りたい場合もあります。足し算と掛け算の役割を変えると、同じ行列状の計算が別の問いへ答えるようになります。

この章の学習目標ブール演算・推移閉包・min-plusを理解し、Warshall法のループ順を説明します。

12.1 数える代わりに存在を判定する

通常の積では候補の組合せを掛け、場合分けを足します。存在だけを知りたいなら、掛け算をAND（両方存在する）、足し算をOR（どれか存在する）へ変えます。このブール行列積のi,j成分は、i→r→jとつなげる中継点rがあるかを表します。

到達可能性を全頂点対でまとめた表を推移閉包と呼びます。本書では長さ0も許す反射的推移閉包を採用し、対角をTrueにします。正の長さの歩道だけを許す流儀では対角の意味が変わるため、この約束を明示します。到達できるなら反復を取り除いた長さN−1以下の単純経路があるので、無限長の歩道を調べる必要はありません。

12.2 Warshall法の不変条件

R[i][j]を到達できるかの真偽値とします。中継に使える頂点を0からkまで増やすとき、iからjへの歩道は、頂点kを使わない場合か、iからk、kからjをつなぐ場合に分かれます。

R[i][j] ← R[i][j] OR (R[i][k] AND R[k][j])

外側のループをkにします。kの処理前には「中継点を0,…,k−1だけ許した到達可能性」が保存され、処理後にはkも許した表になります。これが正しさの帰納的な不変条件です。行列をその場で書き換えても、kを挟むことで新たに利用するk行・k列の値はブール演算の冪等性により問題を起こしません。単に三重ループだからとi,j,kの順を交換すると、この証明は使えなくなります。

12.3 min-plusは経路の費用を合成する

最短費用では、二つの区間をつなぐ操作が加算、候補を選ぶ操作が最小値です。min-plus積をCᵢⱼ=minᵣ(Aᵢᵣ+Bᵣⱼ)と定義します。非辺を∞、単位行列に相当するものの対角を0、それ以外を∞とすると、∞が「候補なし」を表せます。

Floyd–Warshall法ではD[i][j]←min(D[i][j],D[i][k]+D[k][j])とします。辺重みだけを入れた行列のmin-plus k乗は、ちょうどk辺の歩道の最小重みです。対角0を追加すると、そこにとどまる選択が入るため、k辺以下という解釈も可能になります。通常の隣接行列の累乗との意味の違いに注意してください。

12.4 密な出力と疎な入力

辺が少なくても、推移閉包は密になることがあります。一直線の有向経路0→1→…→N−1では入力辺はN−1本ですが、前の頂点から後ろの頂点へ全て到達できるので、出力には約N²/2個のTrueが並びます。疎行列で入力を節約しても、求める答えのサイズまでは消せません。

単一始点だけ知りたければBFSやDFSでO(N+M)、全頂点対の表が必要ならO(N²)の保存先を考えます。大規模な疎行列ではゼロでない成分だけを保存するCSR形式などが有用ですが、演算によって非ゼロ成分が増える「埋め込み」も考慮します。

アルゴリズムの見取り図

対角と直接辺をTrueにする → 中継点kを外側で順に許可 → i→k→jが成立すればi→jをTrueにする

Pythonで確かめる

入力例はプログラム末尾に含まれます。全体をそのまま実行してください。

def warshall(n, edges):
    reach = [[i == j for j in range(n)] for i in range(n)]
    for u, v in edges:
        reach[u][v] = True
    for k in range(n):
        for i in range(n):
            for j in range(n):
                reach[i][j] = reach[i][j] or (reach[i][k] and reach[k][j])
    return reach

R = warshall(3, [(0, 1), (1, 2)])
for row in R:
    print([int(x) for x in row])
assert R[0][2] and not R[2][0]

実行結果

[1, 1, 1]
[0, 1, 1]
[0, 0, 1]

計算量と前提

Warshall法は時間O(N³)、空間O(N²)です。全始点から隣接リスト探索する方法はO(N(N+M))時間で、結果を全て保存するなら空間O(N²+M)です。

第13章　深さ優先探索と幅優先探索

知らない建物を調べるとき、一本の廊下を奥まで進んで戻る方法と、入口から近い部屋を先に埋める方法があります。どちらも到達範囲を調べられますが、処理順序がもたらす保証は異なります。

13.1 DFSは未処理の道を深くたどる

深さ優先探索DFSでは、最近発見した候補を先に処理します。再帰呼出しは暗黙のスタックであり、反復版は明示的なスタックを使います。本章のDFSは隣接リストのどこまで見たかも記録し、再帰と同じように一つの子を探索し終えてから次の子へ進みます。

頂点を訪問済みにするのは、その頂点を発見した時点です。スタックから取り出した時点まで遅らせると、同じ頂点を何度も追加しやすくなります。親から子として採用した辺だけを集めると探索木ができます。元のグラフに閉路があっても探索木自体は閉路を持ちません。元の非木辺が消えたわけではありません。

13.2 BFSは距離の層を広げる

幅優先探索BFSは先に発見した候補を先に処理するキューを使います。始点sの距離を0とし、未訪問の隣vを発見したらd(v)=d(u)+1とします。Pythonではdequeのappendとpopleftで実装します。listの先頭をpop(0)で取り出すと、後続要素をずらす費用がかかります。

BFSのキューには距離が小さい順に頂点が並び、処理中の距離kから新しく見つかる頂点はk+1です。もしvへもっと短い経路があれば、その直前の頂点はより早い層で処理され、vも先に発見されるはずです。これは初回発見時の距離が最短であることの証明です。辺の重みが全部同じ正の値なら辺数最短が費用最短と一致しますが、重みが異なる場合は成立しません。

13.3 なぜ全ての到達可能頂点を訪問できるか

DFSでもBFSでも、訪問した頂点の隣は最終的に全て調べます。到達可能なのに未訪問の頂点が残ると仮定し、始点からそこへの経路上で最初の未訪問頂点を取ります。その直前の頂点は訪問済みなので、その辺を調べたとき発見されるはずで矛盾します。訪問済み管理により無限に同じ閉路を回ることもありません。

非連結グラフの全体を調べるには、全頂点を順に見て、未訪問ならそこから新しい探索を始めます。開始回数が連結成分数です。1回の探索で全頂点に届くと無条件に思い込まないことが重要です。

13.4 経路復元と順序の違い

発見時の親を保存すると、終点から親をたどって始点へ戻り、列を反転するだけで経路を復元できます。BFSの親は最短経路を与えますが、DFSの親は一般には最短ではありません。隣接リストの並びによって親は変わっても、BFSの距離は変わりません。以下のグラフでは0から3への経路は0—1—3と0—2—3の二つがあり、両方とも長さ2です。

アルゴリズムの見取り図

DFS：未訪問の子へ進み、尽きたら戻る。BFS：キュー先頭を取り、未訪問の隣を距離+1で末尾に入れる

from collections import deque

def dfs(adj, start):
    seen = {start}
    order = [start]
    stack = [(start, iter(adj[start]))]
    while stack:
        u, neighbors = stack[-1]
        v = next(neighbors, None)
        if v is None:
            stack.pop()
        elif v not in seen:
            seen.add(v)
            order.append(v)
            stack.append((v, iter(adj[v])))
    return order

def bfs(adj, start):
    distance = [-1] * len(adj)
    parent = [-1] * len(adj)
    distance[start] = 0
    queue = deque([start])
    while queue:
        u = queue.popleft()
        for v in adj[u]:
            if distance[v] == -1:
                distance[v] = distance[u] + 1
                parent[v] = u
                queue.append(v)
    return distance, parent

def restore_path(parent, distance, goal):
    if distance[goal] == -1:
        return None
    path = []
    while goal != -1:
        path.append(goal)
        goal = parent[goal]
    return path[::-1]

adj = [[1,2], [0,3], [0,3], [1,2]]
distance, parent = bfs(adj, 0)
print("DFS:", dfs(adj, 0))
print("距離:", distance)
print("0→3:", restore_path(parent, distance, 3))

距離: [0, 1, 1, 2]
0→3: [0, 1, 3]

第14章　最短経路を求める

最少の乗換回数と最短の所要時間は一致しません。また割引を負の費用としてモデル化すると、使えるアルゴリズムの条件が変わります。最短経路では、入力の性質を先に確かめることが実装選択の中心です。

この章の学習目標緩和を共通原理として、Dijkstra、Bellman–Ford、Floyd–Warshallの条件と計算量を比較します。

14.1 緩和という共通操作

暫定距離d(v)より、uを経由したd(u)+w(u,v)が小さければ更新します。これを緩和と呼びます。初期値は始点だけ0、他は∞です。値が有限になるたび、その値を実現する歩道が見つかったことになります。更新方法が同じでも、どの順に何回行えば十分かがアルゴリズムによって違います。

d(v) ← min(d(v), d(u)+w(u,v))

14.2 Dijkstra法：最小の暫定距離を確定する

全ての辺重みが非負のとき、未確定頂点の中から暫定距離が最小の頂点uを取り、その出辺を緩和します。なぜ確定してよいのでしょうか。uへより短い経路があると仮定し、その経路上の最初の未確定頂点yを考えます。直前の確定頂点を処理した際にyまでの距離が緩和され、そこからuまでの重みは非負なので、yの暫定距離はuより小さいはずです。最小のuを選んだことに反します。

優先度付きキューにheapqを使います。距離が改善されるたび新しい組を追加し、古い組は取り出した際に無視する方式です。0→1が4、0→2が1、2→1が2、1→3が1、2→3が5なら、0の後に2を処理して1を4から3へ更新し、次に1から3を6から4へ更新します。負の辺があると「残りで距離が減らない」という証明が崩れます。偶然正しい出力になっても保証にはなりません。

14.3 Bellman–Ford法：辺数を増やして改善する

全ての辺を順に緩和する処理をN−1回繰り返します。k回の走査後には、少なくともk辺以下で到達できる最短値が反映されます。到達可能な負閉路がなければ最短歩道から閉路を取り除いて単純経路にでき、その辺数は高々N−1なので十分です。途中で更新がなくなれば終了できます。

さらに一回緩和できる辺があれば、始点から到達可能な負閉路が存在します。ただし全ての終点が影響を受けるわけではありません。始点からその負閉路へ進め、そこから終点へ進める場合に、その終点までの歩道の最小重みが−∞になります。以下の実装は到達可能な負閉路が一つでもあれば例外を返す簡潔な仕様です。到達不能な負閉路は報告しません。

14.4 Floyd–Warshall法：全頂点対を扱う

第12章の中継点による分解をminと加算へ置き換えます。負の辺を許せますが、有限な最短距離として読むには関連する負閉路がないことが必要です。全処理後にD[k][k]<0なら負閉路が存在します。iからkへ、kからjへ到達できる組(i,j)はその負閉路の影響を受けます。

無向グラフの負の辺を双方向に通れるなら、その辺を往復するだけで負の閉じた歩道になります。無向の「負辺あり、負閉路なし」を有向の場合と同じ感覚で想定しないでください。頂点の反復を禁止した最短単純経路問題は別の問題です。

方法条件・対象時間（代表的実装）
BFS無重み、単一始点O(N+M)
Dijkstra非負辺、単一始点O((N+M) log(N+1))※
Bellman–Ford負辺可、単一始点O(NM+N)
Floyd–Warshall全頂点対、負閉路に注意O(N³)

※単純グラフで、古い項目を残すヒープ方式の評価です。多重辺を無制限に許せばlog(M+1)と書く方が適切です。

アルゴリズムの見取り図

Dijkstra：最小暫定距離を取り出して緩和。Bellman–Ford：全辺緩和をN−1回。Floyd–Warshall：中継点kを順次許可

from heapq import heappush, heappop
from math import inf

def dijkstra(n, edges, start):
    adj = [[] for _ in range(n)]
    for u, v, weight in edges:
        if weight < 0:
            raise ValueError("negative edge")
        adj[u].append((v, weight))
    distance = [inf] * n
    distance[start] = 0
    heap = [(0, start)]
    while heap:
        cost, u = heappop(heap)
        if cost != distance[u]:
            continue
        for v, weight in adj[u]:
            candidate = cost + weight
            if candidate < distance[v]:
                distance[v] = candidate
                heappush(heap, (candidate, v))
    return distance

def bellman_ford(n, edges, start):
    distance = [inf] * n
    distance[start] = 0
    for _ in range(n - 1):
        changed = False
        for u, v, weight in edges:
            if distance[u] != inf and distance[u] + weight < distance[v]:
                distance[v] = distance[u] + weight
                changed = True
        if not changed:
            break
    for u, v, weight in edges:
        if distance[u] != inf and distance[u] + weight < distance[v]:
            raise ValueError("reachable negative cycle")
    return distance

def floyd_warshall(n, edges):
    distance = [[inf] * n for _ in range(n)]
    for i in range(n):
        distance[i][i] = 0
    for u, v, weight in edges:
        distance[u][v] = min(distance[u][v], weight)
    for k in range(n):
        for i in range(n):
            for j in range(n):
                if distance[i][k] != inf and distance[k][j] != inf:
                    distance[i][j] = min(distance[i][j],
                                         distance[i][k] + distance[k][j])
    if any(distance[k][k] < 0 for k in range(n)):
        raise ValueError("negative cycle")
    return distance

edges = [(0,1,4), (0,2,1), (2,1,2), (1,3,1), (2,3,5)]
print(dijkstra(4, edges, 0))
print(bellman_ford(4, edges, 0))
print(floyd_warshall(4, edges)[0])
negative_edges = [(0,1,4), (0,2,5), (2,1,-3)]
print(bellman_ford(3, negative_edges, 0))

CHAPTER 15

第15章　木の性質を利用するアルゴリズム

全ての頂点から距離を測ると、探索をN回行ってO(N²)かかります。しかし根を隣へ移したとき、近づく頂点と遠ざかる頂点は一辺で分けられます。その差だけを更新すれば、全ての根についての答えをO(N)で得られます。

この章の学習目標直径・中心・重心・LCAを区別し、木DPと全方位木DPを導出します。重心分解の用途も理解します。

15.1 木の直径を2回の探索で求める

直径は全頂点対距離の最大値です。本節は無重みの木です。任意の頂点sから最遠の頂点aを求め、aから最遠の頂点bを求めると、a—bが直径になります。無重みならBFSで距離を得ます。一般グラフではこの2回法は直径を保証しません。非負の重み付き木にも距離和を計算する探索で拡張できますが、負の重みは対象外です。

証明を、sを根にして説明します。直径の端点をx,y、そのLCAをtとします。aがtの部分木外なら、a—xの経路はtを通り、d(a,t)≥depth(a)−depth(t)≥depth(y)−depth(t)=d(y,t)なのでd(a,x)≥d(x,y)です。aがtの部分木内なら、aと違う子側にある直径端点を一つ選べます（tが端点ならtを選びます）。たとえばxを選べば、a—xはtを通り、depth(a)≥depth(y)から同じ不等式が得られます。直径以上の距離は存在しないのでaは直径の端点になり、2回目の最遠点までの距離が直径です。a=tとなる退化例でも、最遠という条件から必要な枝長が0となり結論は変わりません。

15.2 中心と重心は違う最小化

頂点vの離心数をmaxᵤd(v,u)といいます。中心は離心数を最小にする頂点です。無重み木の中心は直径経路の真ん中の1頂点、または隣接2頂点です。どのvも直径両端の少なくとも一方まで⌈D/2⌉以上離れ、直径中央は他の枝へもそれ以上遠くならないことから分かります。もし中央からより遠い枝先があれば、それと直径の遠い側の端を結んで直径を更新してしまいます。

重心は、頂点vを取り除いたときの各連結成分のうち、最大の頂点数を最小にする頂点です。木では、全成分がN/2以下になる頂点がちょうど重心です。大きすぎる成分側へ移動する操作を繰り返せば到達できます。現在の点から最大成分側に一歩進むと、他側はN−大成分サイズとなり、小さくなるためです。重心は1個か隣接2個で、2個の場合はその辺がNを半分ずつに分けます。中心が距離の最悪値を見るのに対し、重心は分割後の個数を見ます。

15.3 LCAと木DP

根付き木の二頂点u,vの共通祖先のうち最も深いものが最小共通祖先LCAです。根を変えるとLCAも変わります。深さが違えば深い方を持ち上げ、同じ深さで一致するまで両方を親へ進めれば求まります。多くの照会には2ʲ個上の祖先up[j][v]を前計算する二分累乗法が有効で、前処理O(N log N)、一照会O(log N)になります。

d(u,v)=depth(u)+depth(v)−2 depth(LCA(u,v))

木DPは子の計算結果を親へ集約する動的計画法です。部分木サイズに加え、部分木内距離和down(v)=Σ子u(down(u)+s(u))を持てます。子から見た距離に対し、親からはその子側の全s(u)頂点へ1歩ずつ増えるからです。独立集合など別の問題では「vを選ぶ・選ばない」の複数状態を持ち、子との制約を状態の組合せで処理します。

15.4 全方位木DP：根を一辺だけ動かす

F(v)=Σᵤd(v,u)を全頂点で求めます。最初に根0からの深さを合計してF(0)を計算します。親vから子uへ根を動かすと、u側のs(u)頂点へは1近づき、残りN−s(u)頂点へは1遠ざかります。したがって差分はN−2s(u)です。

F(u)=F(v)−s(u)+(N−s(u))=F(v)+N−2s(u)

共通の木TではF(0)=6、s(1)=3なのでF(1)=6+5−6=5です。s(2)=1なのでF(2)=6+5−2=9です。頂点1から3,4へ進めばどちらも5+5−2=8。答えは[6,5,9,8,8]となります。まず逆順でsを求め、次に親から子の順でFを伝える二つの走査で済みます。重みwの辺なら差分はw(N−2s(u))です。

一般の全方位木DPでは、隣から届く寄与を全てまとめ、「相手側の寄与を除いた値」をその隣へ返します。除算できない演算でも、隣接先を並べた前方累積・後方累積で各相手を除外できます。合成が結合的なら、一頂点の次数の二乗を避けて全体O(N)へできる場合があります。今回の距離和では差分式がさらに簡潔です。

15.5 重心分解への入口

重心を取り除き、残った各成分で再び重心を探す操作を繰り返すと、成分サイズは各段で半分以下になります。分解の深さはO(log N)です。各段で成分を線形走査すれば構築O(N log N)で、重心を根とする別の分解木ができます。この分解木の辺は元の木の辺とは限りません。

たとえば「色の付いた頂点までの最短距離」を更新付きで照会する問題では、各頂点と分解木上の祖先重心との距離を前計算して利用できます。単発の距離和だけなら全方位木DPの方が簡単で速く、重心分解を使う必要はありません。強力な技法も目的に応じて選びます。

アルゴリズムの見取り図

from collections import deque

def bfs_tree(adj, start):
    distance = [-1] * len(adj)
    parent = [-1] * len(adj)
    distance[start] = 0
    queue = deque([start])
    while queue:
        u = queue.popleft()
        for v in adj[u]:
            if distance[v] == -1:
                distance[v] = distance[u] + 1
                parent[v] = u
                queue.append(v)
    return distance, parent

def diameter_path(adj):
    distance, _ = bfs_tree(adj, 0)
    a = max(range(len(adj)), key=distance.__getitem__)
    distance, parent = bfs_tree(adj, a)
    b = max(range(len(adj)), key=distance.__getitem__)
    path = []
    u = b
    while u != -1:
        path.append(u)
        u = parent[u]
    return distance[b], path[::-1]

def reroot_sums(adj):
    # 前提: 1頂点以上の無重み木
    n = len(adj)
    parent = [-2] * n
    parent[0] = -1
    depth = [0] * n
    order = [0]
    for u in order:
        for v in adj[u]:
            if parent[v] == -2:
                parent[v] = u
                depth[v] = depth[u] + 1
                order.append(v)
    size = [1] * n
    for u in reversed(order[1:]):
        size[parent[u]] += size[u]
    answer = [0] * n
    answer[0] = sum(depth)
    for u in order[1:]:
        answer[u] = answer[parent[u]] + n - 2 * size[u]
    centroids = []
    for u in range(n):
        largest = n - size[u]
        for v in adj[u]:
            if parent[v] == u:
                largest = max(largest, size[v])
        if largest * 2 <= n:
            centroids.append(u)
    return answer, centroids

def prepare_lca(adj, root=0):
    depth, parent = bfs_tree(adj, root)
    parent[root] = root
    up = [parent]
    for _ in range(1, len(adj).bit_length()):
        old = up[-1]
        up.append([old[old[v]] for v in range(len(adj))])
    return depth, up

def lca(u, v, depth, up):
    if depth[u] < depth[v]:
        u, v = v, u
    difference = depth[u] - depth[v]
    for j in range(len(up)):
        if (difference >> j) & 1:
            u = up[j][u]
    if u == v:
        return u
    for j in range(len(up) - 1, -1, -1):
        if up[j][u] != up[j][v]:
            u, v = up[j][u], up[j][v]
    return up[0][u]

adj = [[1,2], [0,3,4], [0], [1], [1]]
length, path = diameter_path(adj)
centers = path[(len(path)-1)//2:len(path)//2+1]
print("直径:", length, path)
print("中心:", centers)
print("距離和と重心:", reroot_sums(adj))

第16章　最小全域木とUnion-Find

全ての拠点を配線でつなぎ、総工事費を最小にしたいとします。どの拠点からの距離も最短にする要求とは異なります。ネットワーク全体の辺の合計を最小化する問題が最小全域木です。

この章の学習目標全域木と最小全域木を定義し、カットの性質からKruskal・Primを理解します。

16.1 何を最小にするのか

連結な無向重み付きグラフGの全域木のうち、辺重みの合計Σₑw(e)を最小にするものを最小全域木MSTと呼びます。負の重みも許されます。そもそも木には閉路がないので、同じ負閉路を回って費用を下げる問題は起きません。グラフが非連結なら全域木は存在せず、各成分の最小全域木を合わせた最小全域森を求められます。

最短経路木は一つの始点からの距離を最小にする親辺の集まりです。0—1が2、0—2が2、1—2が1なら、根0の最短経路木は0—1と0—2で合計4ですが、MSTは1—2と他の一辺で合計3です。MSTで0から全ての距離が最短になるとは限りません。

16.2 カットと交換論法

頂点集合を空でないSとV\Sに分割したものをカットと呼びます。両側を結ぶ辺を横断辺とします。あるMSTの一部として既に採用可能な辺集合Fがあり、カットがFのどの辺も横断しないとき、そのカットを横断する最小重み辺eをFへ追加しても、どれかのMSTへ拡張できます。

証明は交換です。Fを含むMST Tがeを既に持てば終了です。持たなければeを加えると閉路が一つでき、その閉路には別の横断辺fがあります。カットはFを横断しないのでfはFの辺ではありません。eは最小だからw(e)≤w(f)で、fを除けばFとeを含む、重みが増えない全域木になります。Tが最小だったので、交換後もMSTです。同重みでも成立しますが、MSTが一意とは限りません。

16.3 Kruskal法とPrim法

Kruskal法は全辺を軽い順に並べ、両端が違う成分なら採用します。同じ成分なら閉路になるので捨てます。成分の判定と統合にはUnion-Findを使います。次に採用する辺の一端が属する成分をカットの片側にすれば、交換論法で安全性が説明できます。

Prim法は一つの頂点から始め、既に取り込んだ頂点集合と外側を結ぶ最小の辺で一つずつ広げます。こちらも毎回カットの最小辺を選びます。Dijkstra法に似たヒープを使いますが、キーは始点からの距離和ではなく、現在の集合へ接続する一本の辺の重みです。そこを混同すると違う問題を解いてしまいます。

16.4 手計算と実務での注意

辺(0,1,1)、(1,2,2)、(0,2,4)、(2,3,1)、(1,3,5)を考えます。重み1の二辺、次いで重み2の辺を採用すると全頂点が連結し、総和4です。残り二辺は閉路を作るので不要です。

配線や通信の接続費用の基礎モデルになりますが、容量、電圧降下、信頼性、配管径、施工順序を自動的に満たすわけではありません。MSTはどの辺も橋なので、一本の故障で切断します。冗長性を求める設計では辺追加や別の最適化制約が必要です。有向の供給関係には有向全域木など別の定式化を考えます。

from heapq import heappush, heappop

class UnionFind:
    def __init__(self, n):
        self.parent = list(range(n))
        self.size = [1] * n
    def find(self, x):
        while self.parent[x] != x:
            self.parent[x] = self.parent[self.parent[x]]
            x = self.parent[x]
        return x
    def union(self, a, b):
        a, b = self.find(a), self.find(b)
        if a == b:
            return False
        if self.size[a] < self.size[b]:
            a, b = b, a
        self.parent[b] = a
        self.size[a] += self.size[b]
        return True

def kruskal(n, edges):
    if n < 1:
        raise ValueError("empty graph")
    uf = UnionFind(n)
    chosen = []
    total = 0
    for u, v, weight in sorted(edges, key=lambda e: e[2]):
        if uf.union(u, v):
            chosen.append((u, v, weight))
            total += weight
    if len(chosen) != n - 1:
        raise ValueError("disconnected graph")
    return total, chosen

def prim(n, edges):
    if n < 1:
        raise ValueError("empty graph")
    adj = [[] for _ in range(n)]
    for u, v, weight in edges:
        adj[u].append((v, weight))
        adj[v].append((u, weight))
    used = [False] * n
    heap = [(0, 0)]
    total = count = 0
    while heap:
        weight, u = heappop(heap)
        if used[u]:
            continue
        used[u] = True
        total += weight
        count += 1
        for v, cost in adj[u]:
            if not used[v]:
                heappush(heap, (cost, v))
    if count != n:
        raise ValueError("disconnected graph")
    return total

edges = [(0,1,1), (1,2,2), (0,2,4), (2,3,1), (1,3,5)]
print(kruskal(4, edges))
print(prim(4, edges))
assert kruskal(4, edges)[0] == prim(4, edges) == 4

第17章　意思決定を木構造で表現する

麻雀で一枚切ると、その後に相手の打牌、ツモ、自分の次の選択が続きます。将来を枝分かれとして描くことはできますが、見えていない牌を知っているかのように評価すると、現実には実行できない戦略になります。

この章の学習目標意思決定木、ミニマックス、αβ枝刈り、MCTSを区別し、不完全情報の制約を説明します。

17.1 選択と偶然を分ける

意思決定木の各頂点は、その時点の状態または履歴です。自分が選べる分岐と、抽選や他者の行動による分岐を区別します。終端には利益、得点、損失などの評価を置き、どの基準で良さを決めるか明示します。機械学習で特徴量を分ける分類用の決定木も木構造ですが、本章の逐次意思決定の木とは目的が異なります。

ゲーム木は履歴を展開したものです。同じ盤面へ異なる順番で到達しても、履歴木では別の頂点になります。将来に必要な情報が完全に一致するなら状態を共有してグラフへ圧縮できますが、手番、残り資源、反復ルールなどを落とすと不正な合併になります。

17.2 ミニマックスと帰納的な正しさ

二人・零和・完全情報・確定的な有限ゲームを考えます。評価値を常に自分側の得点として統一し、自分の手番では子の最大値、相手の手番では最小値を取ります。終端の評価が正しく、両者がその評価に対して最善に行動するなら、葉からの帰納法により各頂点の値も正しいと分かります。

左の選択の先で相手が3と5を選べ、右の先で2と9を選べるなら、左はmin(3,5)=3、右はmin(2,9)=2、根はmax(3,2)=3です。最大の葉9に目を奪われると、相手に2を選ばれることを見落とします。確率による分岐ではminの代わりに期待値Σpᵢvᵢを取りますが、確率の根拠が必要です。

17.3 αβ枝刈りは不要な比較を省く

αはMAX側が既に確保できる下限、βはMIN側が既に確保できる上限です。探索中にα≥βになれば、その先を詳しく調べても祖先の選択を改善できません。上の例で左の値3を見た後、右のMIN節点で最初の葉2を見たら、右の最終値は2以下です。残りの9を読む必要がありません。

これは近似ではなく、同じ葉評価と探索深さに対してミニマックス値を保つ省略です。ただし評価関数で途中打切りをすれば、元のゲームに対する値は近似になります。最悪では枝刈りが効かずO(bᵈ)、理想的な手順序ではO(b^(d/2))程度まで減る場合があります。bは分岐数、dは深さです。

17.4 モンテカルロ木探索

MCTSは、全ての枝を同じ深さまで読む代わりに、試行を有望な枝へ配分します。典型的には「選択→拡張→シミュレーション→結果の逆伝播」を繰り返します。選択では平均報酬の高い枝を使いたい一方、試行回数が少ない枝も調べる必要があります。UCTという方式では、子iの平均報酬Qᵢと試行回数nᵢ、親の回数nを使い、Qᵢ+c√(ln n/nᵢ)などを最大にします。未訪問の枝は先に試し、cで探索の強さを調整します。

シミュレーションの方策が偏っていれば平均値も偏ります。有限の試行で最善手が保証されるわけではありません。相手の手番でどちらの立場の報酬を最大化するか、確率節点をどう抽選するかも実装で明示します。名前に「木」が付いても、完全情報・不完全情報の問題が自動的に解決されることはありません。

17.5 麻雀を単純なミニマックスにしない

麻雀では他家の手牌や山が見えず、確率的なツモがあり、三人または四人で競います。二人零和の完全情報ミニマックスをそのまま適用する前提はありません。見えている情報が同じ履歴をまとめた情報集合を考え、同じ情報集合では同じ行動方針を選ばなければなりません。隠れた状態ごとに最適な打牌を別々に選んでから平均すると、実際には知らない情報を使う「戦略の融合」の問題が起きます。

簡易モデルとして、切る牌Aの結果を和了+8000が0.2、放銃−6000が0.1、それ以外0が0.7と仮定すれば期待値は1000です。Bが和了+4000を0.3、放銃−2000を0.05とすれば期待値は1100です。これは排他的・網羅的な架空の結果分布であり、実戦確率ではありません。点数期待値と着順期待値も異なります。第20章では、こうした仮定を明示した小さな木だけを計算します。

def minimax(node, maximizing=True):
    if isinstance(node, (int, float)):
        return node
    values = [minimax(child, not maximizing) for child in node]
    return max(values) if maximizing else min(values)

def alpha_beta(node, maximizing=True,
               alpha=float("-inf"), beta=float("inf"), visited=None):
    if visited is None:
        visited = []
    if isinstance(node, (int, float)):
        visited.append(node)
        return node
    value = float("-inf") if maximizing else float("inf")
    for child in node:
        candidate = alpha_beta(child, not maximizing, alpha, beta, visited)
        if maximizing:
            value = max(value, candidate)
            alpha = max(alpha, value)
        else:
            value = min(value, candidate)
            beta = min(beta, value)
        if alpha >= beta:
            break
    return value

tree = [[3, 5], [2, 9]]
visited = []
print("全探索:", minimax(tree))
print("枝刈り:", alpha_beta(tree, visited=visited))
print("読んだ葉:", visited)
assert visited == [3, 5, 2]

第18章　工学と組織に現れるグラフ

製品構成は木、設計変更の波及はDAG、配管の接続は一般グラフ。実務で現れる構造に一つの型を押し付けると、共通部品や循環する関係が消えてしまいます。何を頂点にしたかが計算の意味を決めます。

この章の学習目標BOM、故障解析、WBS、組織、配管のモデルを使い分け、単純化の限界を点検します。

18.1 BOMは「現物の出現」か「品目」か

完成品の中にユニットAとBがあり、どちらにも同じ品目のねじが含まれるとします。組付け位置ごとの現物出現を頂点とすれば、ねじは別々の葉として木に展開できます。品目番号を頂点とすると、同じねじ頂点へAとBの両方から辺が入るDAGになります。共通化した品目を木として一度だけ表示すると、もう一方の使用関係が失われます。

辺には一親当たりの使用数量を持たせます。製品0がAを2個、Bを1個使い、Aがねじを3個、Bがねじを4個使うなら、必要ねじ数は2×3+1×4=10個です。異なる品目数を数える問題なら同じねじは1品目です。「使用個数」と「到達可能な品目数」では集計規則が違います。

18.2 DAG上の数量展開と変更波及

親から子へ辺を向けたBOMで、全ての親の必要量が確定してから子へ配れば、重複参照を正しく加算できます。この順序がトポロジカル順序です。循環があると、製品が間接的に自分を含むことになり、通常の静的BOMとしては入力エラーです。リサイクルや返却容器の循環を扱うなら、単なる構成数量とは違うフローモデルに切り替えます。

共通部品の変更影響を調べるときは辺を逆向きにたどり、その部品を使う親、その親を使う上位品目へ広げます。ただし到達することは影響候補を示すだけです。互換性、適用時期、製番、ソフトウェア版、サービスBOMと量産BOMの差異も判定に必要です。グラフ探索だけで変更可否を確定しないようにします。

18.3 フォルトツリーと論理の付加

フォルトツリーは上位の故障事象をANDゲートやORゲートで下位事象へ分解します。単なる辺は「複数の入力の全てが必要か、どれかで十分か」を表しません。ゲートを頂点にし、その論理を属性として保存します。同じ基本事象が複数箇所に現れると、図を木に展開していても事象は独立ではありません。

独立な事象A,Bなら、ANDの確率はP(A)P(B)、ORはP(A)+P(B)−P(A)P(B)です。しかし共通電源の故障が両方へ現れる場合などは独立性を仮定できません。同じ事象を別々に数えて二重に掛けると、故障確率を過小評価しえます。FMEAの故障モード間の関係も、因果を表すのか単なる関連を表すのかを先に定めます。

18.4 組織図、WBS、依存関係

正式な上司を一人に限定した組織図は根付き木にしやすいですが、実際の相談、承認、技術支援、兼務は追加の辺を持ちます。組織図上の距離が近いことと、情報が早く伝わることは同じではありません。頂点を人にするか役割にするかでも解釈が変わります。

WBSは仕事を成果物へ分解する包含の階層です。工程の先行制約は、ある作業の完了後に別の作業を始める関係で、通常はDAGです。WBSの親子と依存関係を同じ辺に混ぜると、「含まれる」と「先に終わる」が区別できません。DAGの最長重み付き経路からクリティカルパスを求められますが、人員や設備の競合まで自動的に解決するわけではありません。

18.5 配管と配線は接続に物理を重ねる

配管分岐を頂点、管区間を辺にすると、流量保存は頂点での入出量の一致として書けます。環状配管では閉路があり、木の一意な経路という性質は使えません。圧力と流量の関係、熱交換、二相流、振動、支持条件などは追加の方程式や属性です。

三つ以上の部品が一つの治具で同時拘束されるなど、関係そのものが多対象の組ならハイパーグラフが自然な場合もあります。一方、治具を独立した頂点に追加して二部グラフにする表現も可能です。必要な問い合わせに答えられ、意味を保てる表現を選ぶことが重要です。

from collections import deque

def explode_bom(n, edges, product, units=1):
    adj = [[] for _ in range(n)]
    indegree = [0] * n
    for parent, child, quantity in edges:
        adj[parent].append((child, quantity))
        indegree[child] += 1
    queue = deque(v for v in range(n) if indegree[v] == 0)
    demand = [0] * n
    demand[product] = units
    processed = 0
    while queue:
        u = queue.popleft()
        processed += 1
        for v, quantity in adj[u]:
            demand[v] += demand[u] * quantity
            indegree[v] -= 1
            if indegree[v] == 0:
                queue.append(v)
    if processed != n:
        raise ValueError("BOM contains a cycle")
    return demand

edges = [(0,1,2), (0,2,1), (1,3,3), (2,3,4)]
print(explode_bom(4, edges, 0))
assert explode_bom(4, edges, 0)[3] == 10

第19章　グラフ理論の発展的な世界

接続を調べるだけでなく、仕事の順序、担当者の割当て、輸送量、時間帯の競合もグラフで表せます。ここでは問題名の一覧にとどめず、小さな例で何を入力し何を答えるかを確認します。

この章の学習目標DAG、二部グラフ、マッチング、最大流、彩色、中心性、GNNの入口を理解し、適切な問題へ翻訳します。

19.1 DAGとトポロジカルソート

DAGは有向閉路を持たない有向グラフです。DAGの全頂点を、各辺u→vでuがvより前に現れるように並べることをトポロジカルソートと呼びます。入次数0の頂点を取り除き続けるKahn法で求められます。残った頂点があるのに入次数0がなければ、入辺を逆にたどると有限個の頂点のどこかを反復して有向閉路ができるため、DAGではありません。

0→1、0→2、1→3、2→3なら、0,1,2,3と0,2,1,3がどちらも正解です。DAGだから根が一つ、親が一人とは限りません。また向きを無視するとこの例には閉路があります。無向の木とDAGは同じものではありません。

19.2 二部グラフとマッチング

頂点をUとWの二組に分け、同じ組の中に辺がないグラフが二部グラフです。人と仕事、設備と加工可能部品などが例です。二部性はBFSで隣を交互に二色へ塗ることで調べられます。既に同じ色の頂点へ辺があれば失敗です。二部グラフは奇数長の閉路を持たず、逆も成立します。奇数閉路では交互の色が最後に衝突し、色の衝突が起きれば探索木の経路と衝突辺から奇数閉路を取り出せます。

マッチングは端点を共有しない辺の集合です。「人0は仕事0,1が可能、人1は仕事0だけ可能」なら、先に0を仕事0へ割り当てるだけでは人1が余ります。交互に未採用辺・採用辺をたどり、0を仕事1へ移せば、人1を仕事0へ割り当てて2組にできます。このような増加道を見つけて辺の採否を反転させます。増加道がないマッチングが最大である理由は、より大きいマッチングとの差集合を取ると、必ず採用数を一つ増やす交互道が現れるからです。

19.3 最大流と最小カット

有向辺に非負の容量c(u,v)を置き、始点sから終点tへ送る量を最大化します。各辺で0≤f(u,v)≤c(u,v)、中間頂点では流入量と流出量が一致する条件を課します。始点から出る正味の量が流量です。切断S,V\Sでs∈S、t∉Sなら、流量はSから外へ出る容量の和以下です。これがカットによる上界です。

残余グラフには、まだ増やせる順方向容量と、既に流した量を取り消せる逆方向容量を置きます。残余のs→t経路があれば、その最小残余容量だけ流量を増やします。増加道がなくなったとき、残余でsから到達できる集合Sを取ると、外向き辺は飽和し、内向きの流れは0です。したがって現在流量とこのカット容量が一致し、これ以上増やせません。これが最大流・最小カット定理の構成的な説明です。

s→a容量3、s→b容量2、a→t容量2、b→t容量3、a→b容量1なら、s-a-tへ2、s-a-b-tへ1、s-b-tへ2を流して合計5です。sから出る容量も5なので最適です。増加道を毎回BFSで選ぶEdmonds–Karp法はO(NM²)時間です。二部マッチングも、始点→人→仕事→終点へ容量1の辺を置く最大流へ変換できます。

19.4 グラフ彩色

隣接頂点を異なる色に割り当てる頂点彩色は、同時に実施できない試験や、干渉する通信の時間帯割当てを表せます。三角形は3色、四角形の閉路は2色で塗れます。番号順に、隣の使用色を避けて最小の色を付ける貪欲法は簡単ですが、最少色数を保証しません。頂点順を変えるだけで使用色数が変わる場合があります。

最大次数をΔとすると、処理時に禁止される色は高々Δ色なので、貪欲法はΔ+1色以内で塗れます。これは上界で、最適値とは限りません。一般のk彩色判定はk≥3でNP完全です。二部性の2彩色判定が線形時間なのと対照的です。

19.5 中心性とグラフニューラルネットワーク

次数中心性は直接の接続の多さ、近接中心性は他頂点への距離、媒介中心性は最短経路上に現れる割合を評価します。どれが「重要」かは目的で違います。非連結グラフでは距離の∞をどう扱うか、向き付きならどちらへ到達する距離かを定義します。媒介中心性が高くても、情報や流量が本当に最短経路を使うとは限りません。

GNNは、頂点特徴を隣接関係に沿って集約し、学習可能な関数で更新するモデルの総称です。たとえばhᵥの次層をφ(hᵥ, Σᵤ∈N(v) ψ(hᵤ))と書けば、隣の特徴を順序によらない和で集めています。第9章のAxはこの集約の簡単な原型です。層を重ねると遠方の情報を受け取れますが、有限層では見える範囲が限られ、異なるグラフを区別できない場合もあります。学習結果は因果や物理法則の証明にはなりません。

from collections import deque

def topological_sort(n, edges):
    adj = [[] for _ in range(n)]
    indegree = [0] * n
    for u, v in edges:
        adj[u].append(v)
        indegree[v] += 1
    queue = deque(v for v in range(n) if indegree[v] == 0)
    order = []
    while queue:
        u = queue.popleft()
        order.append(u)
        for v in adj[u]:
            indegree[v] -= 1
            if indegree[v] == 0:
                queue.append(v)
    if len(order) != n:
        raise ValueError("directed cycle")
    return order

def maximum_matching(neighbors, right_count):
    # 左頂点uから可能な右頂点の番号をneighbors[u]に格納
    matched = [-1] * right_count
    def augment(u, seen):
        for v in neighbors[u]:
            if v in seen:
                continue
            seen.add(v)
            if matched[v] == -1 or augment(matched[v], seen):
                matched[v] = u
                return True
        return False
    for u in range(len(neighbors)):
        augment(u, set())
    return sorted((u, v) for v, u in enumerate(matched) if u != -1)

print(topological_sort(4, [(0,1),(0,2),(1,3),(2,3)]))
print(maximum_matching([[0,1], [0]], 2))

[(0, 1), (1, 0)]

20.1 鉄道ネットワーク：最短と最少を区別する

駅0,1,2,3に、0—1が4分、0—2が1分、2—1が2分、1—3が1分、2—3が5分の路線があります。無向辺とし、待ち時間は含めません。0から3の辺数最少は2ですが、時間最短は0—2—1—3の4分です。2辺の0—1—3は5分、0—2—3は6分なので、乗換回数と時間のトレードオフを確認できます。

実際の鉄道では出発時刻や乗換待ちを追加します。駅を頂点にした静的な重みだけでは、特定の便に間に合うかを表せないことがあります。必要なら「駅・時刻」を状態にしてグラフを拡張してください。最短時間4という結論は、この架空モデルの条件の下でのみ成立します。

20.3 最小全域木：同じ路線を別の目的で選ぶ

この入力では最短経路に現れる辺とMSTが一致しますが、一般にはそうなりません。第16章の反例と合わせて確認してください。たまたま一致した一例から二つの問題が同じだと結論してはいけません。小さいグラフならN−1本の辺の全組合せを試し、連結な候補の最小値と照合できます。

20.4 行列の歩道計算：反復を具体的に列挙する

三角形で長さ3の0→1歩道は、0→1→0→1、0→1→2→1、0→2→0→1の三つです。どれも頂点を反復しているので、長さ3の単純経路はありません。A³の(0,1)成分3は正しい一方、それを「単純経路が3本ある」と読むのは誤りです。

ここでは行列積の反復でA³を求めます。長さが小さいうちは全歩道を再帰列挙して照合できます。計算結果を別の定義に基づく手段で確かめると、コード同士が同じ誤りを共有する危険を減らせます。

20.5 全方位木DP：全始点BFSを検算用にする

共通の木Tで、O(N)の全方位計算と、各頂点からBFSして距離を足すO(N²)の方法を比較します。遷移式を再実装して照合するだけでは同じ符号ミスを繰り返すかもしれません。BFSは独立に距離の定義を計算するので、検算として適しています。

特にN=1、一本の長い道、星、ランダムな木を試します。一本の道では中央の距離和が最小、星では中心が最小です。頂点番号を置換しても対応する答えが同じになることは、根0に依存した不正な実装を検出する手掛かりになります。

20.6 麻雀の簡易ゲーム木と自由課題

第17章の架空の排他的結果分布を使い、打牌Aは期待値1000、Bは1100と計算します。ここで実装するのは一段の意思決定と確率分岐だけで、牌効率、他家戦略、着順条件、情報集合を扱う実戦AIではありません。確率が負でないこと、合計が1であることも検査します。

自由課題では、自分の仕事や趣味から一つ選び、「頂点の同一性」「辺の意味」「方向」「重みの単位」「除外した現実の制約」を記したモデル仕様を作ってください。少数頂点の手計算、算法の前提、反例、コード、期待出力、結果の限界を揃えれば、説明可能な計算になります。グラフ理論の価値は、現実の全てを表現し尽くすことではなく、問うべき関係を明確にし、検算可能な手順へ変えることにあります。

from collections import deque
from heapq import heappush, heappop
from math import inf, isclose

# 1. 鉄道: 非負・無向の重み
edges = [(0,1,4), (0,2,1), (2,1,2), (1,3,1), (2,3,5)]
adj = [[] for _ in range(4)]
for u, v, w in edges:
    adj[u].append((v,w))
    adj[v].append((u,w))
distance = [0, inf, inf, inf]
heap = [(0,0)]
while heap:
    cost, u = heappop(heap)
    if cost != distance[u]:
        continue
    for v, w in adj[u]:
        if cost + w < distance[v]:
            distance[v] = cost + w
            heappush(heap, (cost+w,v))
print("鉄道:", distance)

# 2. BOM: この入力では[0,1,2,3]がトポロジカル順
bom = [[(1,2),(2,1)], [(3,3)], [(3,4)], []]
demand = [2,0,0,0]
for u in [0,1,2,3]:
    for v, q in bom[u]:
        demand[v] += demand[u] * q
print("BOM:", demand)

# 3. MST: 小規模な辺列をKruskal法で選択
parent = list(range(4))
size = [1]*4
def find(x):
    while parent[x] != x:
        parent[x] = parent[parent[x]]
        x = parent[x]
    return x
total = 0
chosen = []
for u,v,w in sorted(edges, key=lambda e:e[2]):
    a,b = find(u),find(v)
    if a != b:
        if size[a] < size[b]:
            a,b = b,a
        parent[b] = a
        size[a] += size[b]
        total += w
        chosen.append((u,v,w))
assert len(chosen) == 3
print("MST:", total)

# 4. 行列: A³の歩道数
A = [[0,1,1],[1,0,1],[1,1,0]]
P = [[int(i==j) for j in range(3)] for i in range(3)]
for _ in range(3):
    P = [[sum(P[i][r]*A[r][j] for r in range(3))
          for j in range(3)] for i in range(3)]
print("3歩の0→1:", P[0][1])

# 5. 木: 全方位DPと全始点BFSを比較
T = [[1,2],[0,3,4],[0],[1],[1]]
n = len(T)
par = [-2]*n
par[0] = -1
order = [0]
depth = [0]*n
for u in order:
    for v in T[u]:
        if par[v] == -2:
            par[v] = u
            depth[v] = depth[u]+1
            order.append(v)
subtree = [1]*n
for u in reversed(order[1:]):
    subtree[par[u]] += subtree[u]
answers = [sum(depth)]+[0]*(n-1)
for u in order[1:]:
    answers[u] = answers[par[u]] + n - 2*subtree[u]
brute = []
for start in range(n):
    dist = [-1]*n
    dist[start] = 0
    queue = deque([start])
    while queue:
        u = queue.popleft()
        for v in T[u]:
            if dist[v] == -1:
                dist[v] = dist[u]+1
                queue.append(v)
    brute.append(sum(dist))
assert answers == brute
print("全方位:", answers)

# 6. 架空の打牌結果分布: (確率, 点数)
actions = {"A": [(0.2,8000),(0.1,-6000),(0.7,0)],
           "B": [(0.3,4000),(0.05,-2000),(0.65,0)]}
values = {}
for name, outcomes in actions.items():
    assert all(p >= 0 for p, reward in outcomes)
    assert isclose(sum(p for p, reward in outcomes), 1.0)
    values[name] = sum(p*reward for p,reward in outcomes)
print("架空期待値:", values)
print("選択:", max(values, key=values.get))
